## 结论

> **三层不是一条流水线，是数据端的三次独立交付。所以「修好上游就好了」不成立 —— 每一层都有只可能在它自己身上产生的错。**

## 1 血缘：三次交付

```
交易所
 │
 ├─→ Level-1 逐笔行情
 │     外部 SQL Server: qtg_data.tbl_future_book_l1
 │     ★ 仓库内零数据落地，只有 SQL 点查
 │
 └─→ 通联（数据端）
       │
       ├─→ txt 层    future_pricemin{YYYYMMDD}.txt   全市场全合约 1 分钟
       │
       └─→ pkl 层    all_symbol_min_full_main_close_k_1.pkl
                      79 品种主力连续 + 复权因子 K
                      ★ 单独交付，不是本地从 txt 拼出来的
                      │
                      └─→ src/data/prepare_v3_minute.py   ← 唯一的本地加工
                            clean_1m/   ← 回测唯一读取入口
```

**Level-1 → txt 那条箭头是虚线。** 合成算法未知，甚至不确定 txt 是从 Level-1 合成的：实测同一根 bar 的 `volume` 完全吻合、`high` 一个 8209 一个 8207。量对得上、价对不上。

> **Level-1 只能当仲裁旁证，不能当 txt 的逐字段对账基准。**
> 它能回答「这个现象在源头存不存在」，回答不了「这一根 bar 的四个价对不对」。

**这件事的三条推论**（后面所有内容都建立在这上面）：

- **pkl 有一整类 txt 里不可能存在的错** —— K、主力判定、时间戳重复。txt 根本没有这些字段，这些错只可能在 pkl 的加工环节产生。
- **txt 有一整类 pkl 里不可能存在的错** —— vwap、成交额口径。pkl 没有 `vwap` 列，这类错止步于 txt。
- **两层是独立验证，不是互相校对。** txt 侧用 awk 单遍扫 3,989 个文件，pkl 侧用 pandas 扫 6,628 万行，两条互不共享代码的链路对同一现象给出同向结论，是可信度加成。

### 逐字段含义

> 权威版在 `data/00-跨层/v3.2-SPEC-三层数据已知事实.md` 的 §1.1 / §2.2 / §3.1，那里带证据与实测数字。这里是同一套定义的压缩版。

**pkl 层 —— 11 列（index 是 `datetime`）**

| 字段 | 是什么 | 一句话陷阱 |
|---|---|---|
| `datetime`（index） | bar 时间戳 | **标在分钟末端**：09:01 覆盖 `[09:00, 09:01)`；09:00 是零跨度的集合竞价 |
| `trading_date` | **交易日（结算日）** | 夜盘归属**次一**交易日。日级聚合只能用它，不能用 index 的日期部分 |
| `open` `high` `low` `close` | **这一分钟**的开高低收 | **裸价**，未复权。保证金 / 手数 / 最小变动价位 / 涨跌停一律用它 |
| `volume` | **这一分钟内**的成交量（增量，手） | 不是当日累计 |
| `total_turnover` | **这一分钟内**的成交额（增量，元） | `= 量 × 均价 × 合约乘数`；全历史单双边口径一致 |
| `open_interest` | 该分钟**末**的持仓量（**存量快照**） | 与 `volume` 不同族：volume 差分、OI **不差分** |
| `contract` | 该时点的主力合约代码 | **pkl 独有**。干净品种的换月 100% 在交易日边界 |
| `underlying_symbol` | 品种代码 | **pkl 独有**。`clean_1m` 里丢掉了 —— 变成文件名 |
| `K` | **后复权因子** | **pkl 独有**。**复权价 = `close / K`，是除不是乘**；PM/RI 的坏值是 `K == 0` → 静默 `inf` |

**txt 层 —— 14 列（≤ 2022-09-21，TAB）/ 13 列（≥ 2022-09-22，逗号，无 `Offset`）**

| 字段 | 是什么 | 一句话陷阱 |

**这张表带出的三件事**：

1. **`upper_limit_price` / `lower_limit_price` 填上了一条已知缺口。** `CLAUDE.md` 写着「涨跌停板完全没有实现，也没有数据」—— 数据其实一直在 Level-1 上，配 `pre_settlement_price` 就能复原每合约每交易日的板价。
2. **「P0-3 的 `volume` 完全吻合」需要回头确认比法。** Level-1 是**当日累计**、通联是**分钟增量**，只有先差分才可比。若当时是拿原值直接比而恰好吻合，说明这张表的 `volume` 语义与 CTP 规范不同 —— 那本身就得查。
3. **P0-4「Level-1 给的 OHL 本来就不相等」是弱证据。** 当日累计的 OHL 在竞价结束后的**任何**一条快照上本来就不相等，推不出「竞价那一分钟内部有波动」。要坐实，得取 21:00:00–21:00:59 内的**全部 `last_price`** 看是否为常数。

### 三条搞错就全盘皆错的口径

- **Level-1 的 OHLC 是当日累计的开/高/低，不是那一分钟的**，而且 `close_price` **盘中根本无效**。唯一的「此刻」价格是 `last_price`。直接和通联逐字段比对会全错。
- **txt 的 `TDATE` 是自然日，`CLEARINGDAY` 才是交易日。** 按 `TDATE` 分组会把「D 日日盘」和「归属 D+1 交易日的 D 日夜盘」混在一组。
- **pkl 的复权价 = `close / K`，是除不是乘。** 锚在上市首约（后复权），复权价会离真实价很远（铁矿石 8.63 倍、天然橡胶 0.18 倍）——**保证金、手数、最小变动价位、涨跌停必须用裸 `close`。**

### 三条不能硬编码的

- **每日 bar 数不是常数**，历史上在 226 / 241 / 256 / 346 / 376 / 466 / 556 之间跳，池内 **38/59 个品种**出现过一种以上取值。
- **中金所时段与商品不同**：T / TF / TS 收在 15:15，IC / IF / IH / T / TF / TS 开在 09:15。
- **夜盘收盘分三档**（23:00 / 01:00 / 02:30），且是分批引入的（2013-07 起），2020-02-09 ~ 05-03 全市场停摆。

## 3 每层已知的脏点

### Level-1（3 条 + 2 条待补）

- 含 **efp 合约**，不要引入
- **重复时间戳**（20260203 AU2603 的 19:02:54.500）—— 落地时会撞主键。**先查 `source`**：多路采集也会造成同键重复，那不是数据错误

- **【待补】** 每天 06:00 与 18:00 前后有数据且 OHLC 全为 0
- **【待补】** 白盘/夜盘收盘后有尾数据陆续到达（15:06、15:08）

**三条互不相关的判据（K 损坏、主力判定崩坏、时间戳重复）指向完全相同的名单** —— 剔除这批品种的决定非常稳固。

### 本地 ETL 引入的一条

**`clean_1m` 里残留假 session。** 清洗规则按**日历日**判零成交，但跨零点夜盘品种（AU / AG / SC / AL / CU / ZN / PB / SN / NI / SS / BC）的 00:00–02:30 段落在装着真实日盘的下一个日历日上，于是被留下。AU 的 2025-10-09 还留着一根「假期压缩 bar」（+4.06%，且价格几乎等于次日开盘价）——**回测里会在根本无法交易的时刻触发止损**。正确粒度应是 `(trading_date, session)`。当前的 parquet 是用带这个漏洞的版本生成的。

## 4 pkl 层的数值质量其实很高

容易被上面一堆问题带偏，所以单独记一笔 —— 池内 59 个品种在数值一致性上几乎无瑕：

- `high < low` / `high < max(open, close)` / `low > min(open, close)` —— **全库 0 / 0 / 0**
- OHLC 含 NaN —— **全库 0**；OHLC ≤ 0 —— 全库仅 96 根，**池内为 0**
- 时间戳单调 —— **79/79 全部通过**
- 成交额恒等式：反推合约乘数 908 组，**相对误差 > 1% 的组数 = 0**
- **单双边口径全历史一致**，不存在台阶 → 全历史成交额排名可以直接用

**79 → 59 是四步筛出来的**：K 损坏或主力判定崩坏（剔 7）→ 已死亡（剔 2：BB、FB）→ 流动性消失（剔 2：WR、RR）→ 数据截断**挂起待补**（9，S-1 修好后池子回到 68）。另有 4 个品种设了 `usable_from`（B / SF / SM / CY），**池内 50/59 个品种连一天零成交都没有**。
