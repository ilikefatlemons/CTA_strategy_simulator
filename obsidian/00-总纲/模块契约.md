# 模块契约

每篇模块笔记必须写满的东西。**十节，不得空缺**——沿用 82 案「九个固定字段」的做法：固定格式才能横向比较，空缺本身就是信息。

## frontmatter

```yaml
---
名称: 大周期过滤-2h双均线粘性多空
模块位: 大周期过滤
层: 信号与风控          # 信号与风控 | 执行与数据
状态: 启用              # 启用 | 候选 | 弃用 | 未实现
周期: [2h]
读取: [收盘价, MA21, MA55]
产出: [大周期状态]
参数: [大周期_周期, 大周期_快线, 大周期_慢线, 大周期_价格取值, 大周期_粘性]
版本: v4.0
类型: SPEC
tags: [模块, 模块位/大周期过滤]
---
```

十个键全部必填。含义：

| 键 | 填什么 | 为什么要它 |
|---|---|---|
| `名称` | 与文件名一致 | 重命名时的自检 |
| `模块位` | 它插在哪个插槽 | tag-pane 分面、[[模块位总表]] 反查 |
| `层` | 信号与风控 / 执行与数据 | 决定它属于策略判断还是执行纪律 |
| `状态` | 启用 / 候选 / 弃用 / 未实现 | 只有 `启用` 的模块才被 [[回调策略]] 链到 |
| `周期` | 读哪些周期 | 换周期集时一眼看出哪些模块受影响 |
| `读取` | 读哪些量 | 无未来函数审计的输入 |
| `产出` | 往下游交出什么状态变量 | 换模块时的接口契约——**同位模块必须产出同样的东西** |
| `参数` | 引用了哪些参数 | 与 [[参数总表]] 双向闭合 |
| `版本` `类型` | v4.0 / SPEC | 承接仓库根目录的文档类型码 |
| `tags` | `模块` + `模块位/xxx` | 分面浏览 |

## 正文十节

### 一 职责

**一句话。** 说清这个模块负责回答什么问题。不写实现，不写参数。

### 二 输入契约

读哪个周期、哪些量，以及**读的是哪一根**。这里必须出现「截至 bar i-1 已收盘」这类措辞（见 [[已收盘]]），不能只写「读 30m 的 MA21」。

### 三 判定规则

伪代码 + 真值表。伪代码用中文变量名，与 [[参数总表]] 里的参数名一字不差。真值表要把所有分支列全，包括「什么都不做」那一支。

### 四 输出契约

产出的状态变量、取值域、以及**下游谁在用**。同一个模块位的不同模块，这一节必须完全一样——这就是「可替换」的定义。

### 五 参数与开关

四列表：`参数名` / `默认值` / `含义` / `改了会怎样`。

最后一列是重点，不能写「调大则更严格」这种废话，要写清改动会打开或关闭哪条具体行为。沿用 `src/config.py` 抬头那条约定：

> 每个会改变结果的行为都要有具名开关，好让新旧行为在同一段数据上做 A/B，而不是被静默烤进代码。

### 六 无未来函数

逐条列出「读了什么 → 触及的最新 bar」。任何一条触及 bar i 或更晚的，必须给出理由（比如「这是窗口形状属性，与价格无关，循环开始前就已确定」）。

格式照抄 `src/engine/pullback_v3_backtest.py:17-32` 那张表。汇总在 [[求值顺序与无未来函数审计]]。

### 七 与其他模块位的耦合

用 wikilink 指出：**谁重置我 / 我重置谁 / 谁消费我的产出 / 我依赖谁的产出**。四个方向都要写，没有就写「无」。

### 八 这个模块自身的代价

**只写这个模块本身的代价，诚实点名。** 整套装配层面的问题（模块之间互相拆台那种）一律收到 [[回调策略]] 最后，不在这里写。

没有代价的模块不存在。如果这一节写不出来，说明还没想清楚。

### 九 同位候选与退化关系

本位其他候选的 wikilink（多数是空心节点），以及**退化关系**——「把参数 X 调到 Y，我就退化成同位的另一块」。

退化关系这一节是防重复的：两个模块如果互为退化，其实是一个模块的两个参数点，不该占两篇笔记。判据参考 `docs/04-参考资料/v3.0-ENUM-回调再入场策略编目.md` §0.4「逻辑独立性的判别测试」。

### 十 测试钩子

**这个模块单独可测的断言**，不依赖整条链路。写成 pytest 能落地的句子。

不写绩效数字。任何实证结论都要走 `docs/03-lineB-R-Breaker/B2-策略多样性探索-R-breaker/v4.0-PLAN-R-Breaker策略改进计划.md` §0 那套九字段测试模板，输出分布 + 报告样本量 n。

## 模块位笔记（薄）

模块位笔记不走上面这套，它只有四节：`职责` / `输出契约（本位所有模块必须产出的东西）` / `当前选中` / `本位候选`。

十五行左右就够。它的作用是让图上有 `模块位 → 候选` 这条边。

## 写新模块的流程

1. 在对应的 `位-xxx.md` 的「本位候选」里加一行指向新模块的链接 —— 这时它是空心节点。
2. 写那篇新模块笔记，十节写满，`状态: 候选`。
3. 把参数加进 [[参数总表]]。
4. 要真的跑它：在 [[回调策略]] 装配表里换掉那一行，把新模块 `状态` 改成 `启用`，旧的改成 `候选`。
