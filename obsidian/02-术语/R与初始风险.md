# R与初始风险

```
R = |入场价 − 初始止损价|
```

**一笔交易开出去的那一刻就定死的风险距离。** 它是价格单位，不是钱——真变成钱要乘手数和合约乘数，而 [[位-仓位]] 现在是空的（恒定一手）。

## 在本装配里 R 怎么定

由 [[止损-30m回调低点下方一段ATR]] 算出来：

```
候选止损 = 回调段最低价 − 0.25倍ATR        （多头）
R        = 入场价 − 候选止损
R        = clamp(R, 0.8倍ATR, 3.0倍ATR)     ← 两个夹子
初始止损  = 入场价 − R
```

ATR 是 30m 的 ATR(14)，**入场那一刻取，之后冻结**。

## 两个夹子为什么在

没有夹子，R 完全由回调深度决定，会取到极端值：

- 回调很浅（低点几乎贴着入场价）→ R 极小 → 一点噪声就打掉，且「一个 ATR 的盈利」会显示成 20R，统计全废
- 回调很深 → R 极大 → 单笔亏损远超同组其他交易

夹上之后 **R 始终落在 `[0.8, 3.0] × ATR` 里**，于是「1.5 倍 ATR 的浮盈」这种说法在所有交易之间可比。[[止盈-ATR解锁后追踪]] 的阈值也才有稳定含义。

## R 不参与止盈

值得单独点出来：**本装配的止盈完全不用 R**，用的是 ATR 倍数。

这和现引擎不一样——`src/rules/take_profit.py:21` 的 `partial_trigger_price` 是 `入场价 ± 2R`，2R 到了减半仓。那套做法在 [[止盈-2R减半后吊灯]] 这个候选里保留着。

用 ATR 而不是 R 的理由：R 已经被夹子约束在 ATR 的窄区间里，再用 R 做止盈等于绕一圈回到 ATR，中间还多一层对回调深度的依赖。

## 统计口径

按仓库既有约定（`src/performance/trade_stats.py`）：

- 收益率一律是**净的**（扣掉 `成本_每仓基点`），存普通小数，格式化层再乘 100
- 亏损桶是 `收益 <= 0`（持平算亏，这样胜率和盈亏比自洽）
- 最大回撤是**负**分数，且基于**逐根盯市**的权益曲线——逐笔平仓的权益看不见笔内回撤
- Sharpe 用**日频**权益收益 × `sqrt(252)`，不是 bar 级收益
