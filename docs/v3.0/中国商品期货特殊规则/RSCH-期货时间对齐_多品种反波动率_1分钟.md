# 0. 本文档回答的具体问题

**用途**：多品种独立信号 → 按反波动率一类逻辑分配仓位 → 组合层存在依赖"当前并发持仓"的 cooldown 门控 → 回测。
**频率**：1 分钟。
**时段范围**：待定，第 5 节给出决策依据与结论。

**贯穿全文的核心论断**：这个用途**不需要一张对齐的矩形面板**。它需要三样东西，而这三样的时间要求互不相同：

| 需求 | 真实的时间要求 | 常见错误 |
|---|---|---|
| 单品种信号计算 | 该品种自身的 session 内连续序号 | 用墙钟时间戳，导致滚动窗口跨越"没有市场"的空档 |
| 反波动率仓位 | 跨品种可比的**日频**风险标尺 | 用分钟波动率跨品种比较，标尺被 session 结构污染 |
| 并发持仓门控 | 一个确定的**全局事件序** | 误以为需要"同步采样"，于是 ffill 补齐面板 |

把三者塞进一张 `DataFrame(index=timestamp, columns=instrument)` 并 `.ffill()` 补齐，是同时破坏这三样的最短路径。第 3 节和第 7 节展开。

# 1. 先决问题：交易日 vs 自然日

## 1.1 官方定义

中国期货的**交易日 T** = T−1 日 21:00 夜盘开市 → T 日 15:00 收市。夜盘归属于**次一交易日**。

推论：
- 周一 21:00 的夜盘 K 线属于**周二**交易日
- 周五 21:00 的夜盘属于**下周一**交易日（跨越两个自然日 + 一个周末）
- 夜盘的成交计入次日的成交量、持仓量、结算价
- 节假日前第一个工作日（不含周六日）**不进行夜盘交易**【官方表述见来源】，因此**节后第一个交易日只有日盘**，其开盘集合竞价顺延至 8:55–9:00

## 1.2 按自然日分组会产生什么具体错误

| 错误 | 机理 | 表现 |
|---|---|---|
| 日线收盘价错误 | 自然日分组把当日 21:00 之后的夜盘并入当日 | 你的"收盘价"变成 23:00 / 01:00 / 02:30 的最后一笔，而交易所公布的收盘价是 15:00 的最后一笔 |
| OHLC 跨越两个交易日 | 自然日的高低点混合了交易日 T 的日盘与交易日 T+1 的夜盘 | 最高/最低价不可对账；跳空被抹平 |
| 结算价无法对账 | 结算价是**交易日**全天成交量加权均价（夜盘+日盘） | 按自然日算的 VWAP 覆盖的时段是错的 |
| 涨跌停基准错误 | 涨跌停板以**昨结算价**为基准 | 错误的交易日边界 → 错误的昨结算 → 封板检测全错 |

**对本用途的特殊后果（这一条是关键）**：自然日分组对不同品种造成**不同程度**的错误。

- 21:00–23:00 档：夜盘完全不跨自然日午夜，"当日日盘 + 当晚夜盘"恰好落在同一自然日 → 错位是整段的、干净的
- 21:00–次日 01:00 / 02:30 档：夜盘被午夜**劈成两半**，21:00–24:00 与 00:00–02:30 落入不同自然日 → 错位是撕裂的
- 无夜盘品种：自然日 = 交易日，**完全不受影响**

于是错误强度与"夜盘档位"完全相关。这在单品种回测里只是一个 bug；在你的横截面里，它是一个**与品种分组严格相关的系统性偏差**，会直接扭曲反波动率权重。单品种检查通不出来，必须按档位分组检查（第 8 节 C1/C8）。

## 1.3 正确的边界定义与日历来源

不要用任何通式推算（"前一交易日 21:00"这种写法在节后第一个交易日必然错）。交易日边界是**不规则的**，只能查表：

- 各交易所"通知公告"栏目的《关于 XX 节期间交易时间安排的通知》——同时给出休市日与哪一天取消夜盘
- 广期所官网设有独立的"交易日历"栏目
- 数据商交易日历接口（RQData、TqSdk、AkShare 等各自提供）
- **严禁在代码中硬编码假期日期**。中国法定节假日由国务院办公厅每年年底发布次年安排，含调休，不可提前推算；交易所公告的休市日与法定假日不完全等同

日历表最少需要三列：`trading_date` / `has_night_session`（该交易日是否有**前置**夜盘） / `night_session_start_datetime`。第三列存在的意义是让节后首日的起点自然地变成 9:00 而不是 21:00。

# 2. 缺口(Gap)的类型学

| # | 类型 | 成因 | 可预知 | 应否填充 | 对本用途的处理 |
|---|---|---|---|---|---|
| 1 | 小节休息 10:15–10:30 | 制度性，全商品品种同步 | 是 | **否** | 危害最小（横截面上完全对称）。但滚动指标是否跨小节连续，需显式决定 |
| 2 | 15:00 → 21:00 段间空档 | 制度性 | 是 | **否** | 注意：这个空档**跨交易日**（15:00 是 T 的终点，21:00 是 T+1 的起点），不是日内空档 |
| 3 | 夜盘档位差异 | 23:00 / 01:00 / 02:30 三档 | 是 | **否** | **本用途的核心矛盾源**。23:00 后部分品种冻结、部分仍在交易 |
| 4 | 无夜盘品种 | 品种属性 | 是 | **否** | 广期所全部品种（工业硅、多晶硅、碳酸锂、铂、钯）+ 部分农产品 |
| 5 | 节假日前一交易日全市场无夜盘 | 制度性 | 是（须查日历） | **否** | 这一天全品种同步只有 225 根——**全年唯一天然完美对齐的日子**，可当作对照组 |
| 6 | **涨跌停封板** | 市场开着，价格冻结 | **否** | **见下，逻辑相反** | 价格真实、信号不可成交 |
| 7 | 停牌 / 临时休市 | 交易所公告、系统故障、合约最后交易日 | 部分 | **否** | 整段剔除，该品种当日退出横截面 |

## 2.1 为什么 (6) 与 (1)–(5) 本质不同

(1)–(5)：**市场不存在**。此处没有价格，任何"价格"都是你造出来的，任何在此触发的成交都是虚构的。
(6)：**市场存在，价格真实，但你的单排不到队**。K 线照常生成，OHLC 有意义，成交量可能为 0 或极小。

处理逻辑因此**完全相反**：

| | (1)–(5) | (6) 封板 |
|---|---|---|
| K 线是否应存在 | 否，应为 NaN | **是，不得删除** |
| 是否参与指标计算 | 否 | **是**（价格是真实市场信息） |
| 是否可成交 | 否 | **否** |
| 处理位置 | 数据层剔除 | **执行层拦截，数据层保留** |

**封板对本用途的具体失效模式**：连续封板期间价格不动，分钟收益率恒为 0 → 该品种的分钟波动率估计塌向 0 → **反波动率权重趋向无穷** → 你的组合会在最不可能成交的品种上分配最大仓位。这是一个不报错、不抛异常、只是悄悄给出灾难性权重的失效。第 7 节给出两条独立的补救（日频波动率 + 权重上限），第 8 节 C9 给出检测。

# 3. 对齐方案对比

四种方案并列。**没有"最佳"，只有"在哪一层正确"。**

## 3.1 前值填充 (forward fill)

- **在什么用途下正确**：日终盯市估值、组合净值曲线绘制、需要"任意时刻可查询的最新已知价格"且**保证不在填充点触发交易**的场景
- **破坏了什么**：制造出市场不存在时的 K 线。收益率被注入零值、波动率被系统性低估、成交量类指标失真、任何在填充段触发的信号不可成交
- **检测方法**：`volume == 0` 的 bar 占比；OHLC 四值全等且 volume 为 0 的 bar 占比；逐分钟收益率的零值占比按品种分组比较
- **对本用途**：信号层禁止，执行层禁止，权重计算层禁止。仅可用于净值曲线的可视化

## 3.2 取交集 / inner join

- **在什么用途下正确**：跨品种价差套利、配对交易、任何需要**真正同步**价格的场景。此时非同步的价差是伪价差，必须丢弃
- **破坏了什么**：把面板压缩到"所有品种都在交易"的时间戳。若池子里同时有广期所无夜盘品种和 02:30 档品种，交集恰好等于日盘 225 分钟
- **检测方法**：`panel.dropna().shape[0] / panel.shape[0]`；以及交集时间戳集合是否恰好等于某个 session 组合
- **对本用途的关键警告**：inner join **不是一个中立的技术选择**。在混合档位的品种池上，它是"只用日盘"这个策略决策的**隐蔽版本**——你会在不知情的情况下做出第 5 节那个决策。如果要做，应显式做

## 3.3 事件时间 / session 内序号索引

- **在什么用途下正确**：单品种时间序列指标计算、跨周期重采样。理论依据见 López de Prado 关于时间 bar 统计性质的论述（来源见文末）
- **破坏了什么**：墙钟时间被抹掉。不同品种的"第 N 根 K 线"对应不同的墙钟时刻 → **跨品种横截面比较在此索引下无意义**
- **检测方法**：把序号索引映射回墙钟，检查同一序号下各品种的墙钟时刻是否一致（在混合档位池上必然不一致）
- **对本用途**：**指标层用它是对的，横截面层用它是错的**。这不是矛盾，是分层的必要性

## 3.4 按 session 分段对齐

- **在什么用途下正确**：需要保证滚动窗口不跨越"没有市场"的空档时。每个 session 独立索引，窗口在段首重置
- **破坏了什么**：滚动窗口在每段开头被截断，短窗口指标在段首 window−1 根内失效；含夜盘品种每交易日产生 4 个重启点，有效样本量下降；跨段动量/跳空信息被丢弃
- **检测方法**：检查滚动指标在每段前 window 根是否为 NaN；统计因段首截断损失的 bar 占比
- **对本用途**：是否分段是一个**独立于对齐的建模决策**。对 1 分钟 ATR(14) 这类短窗口，分段代价小；对 MA(240) 这类长窗口，分段等于让它在每段前 4 小时不可用，代价大

## 3.5 三者在本用途下的分工

| 层 | 方案 | 理由 |
|---|---|---|
| 信号/指标 | 3.3（+ 可选 3.4） | 单品种内部事务，不涉及横截面 |
| 组合状态机 | 全局事件队列（下述，非上述四种） | 门控需要全序，但全序 ≠ 同步采样 |
| 仓位权重 | 日频，不在分钟层对齐 | 见第 7 节 |
| 净值可视化 | 3.1 | 唯一可接受 ffill 的地方 |

# 4. 前值填充的具体危害

## 4.1 为什么填充出的 K 线产生不可成交的信号

K 线是"市场曾经存在"的证据。填充出的 K 线背后没有订单簿、没有对手方、没有撮合。信号在此触发，回测按该价格记账，而现实中你在那一刻**连报单都会被拒**（非交易时段报单为废单）。

**螺纹例子（1 分钟，池子含黄金）**：
螺纹 23:00 收市。若面板被扩展到 02:30（因为池中有黄金），螺纹的 23:01–02:30 共 **210 根** K 线被 ffill，close 全部等于 23:00 的收盘价。

- **后果 A（显性）**：任何在这 210 根上触发的信号——追踪止损被触及、回调条件满足、指标交叉——都会被回测记为成交。现实中你在 23:30 对螺纹下不了任何单
- **后果 B（隐性，对本用途更致命）**：这 210 根的收益率恒为 0

## 4.2 后果 B 的量化：反波动率权重被结构性扭曲

一个完整交易日的 1 分钟 bar 数（日盘 75+60+90 = 225）：

| 组 | 夜盘 | 全日 bar 数 | 若面板扩至 555 的有效比例 | 分钟波动率被低估 | **反波动率权重被放大** |
|---|---|---|---|---|---|
| G0 | 无 | 225 | 40.5% | −36.3% | **+57.1%** |
| G1 | 至 23:00 | 345 | 62.2% | −21.2% | **+26.8%** |
| G2 | 至次日 01:00 | 465 | 83.8% | −8.5% | **+9.3%** |
| G3 | 至次日 02:30 | 555 | 100% | 0 | 0 |

（推导：零收益 bar 稀释后 `σ_measured ≈ σ_true × sqrt(有效比例)`；反波动率权重 ∝ 1/σ，故放大倍数 = 1/sqrt(有效比例)。）

**读法**：仅仅因为 `.ffill()` 这一行，广期所品种（工业硅、多晶硅、碳酸锂、铂、钯）会拿到比应得多 **57%** 的仓位，且这个偏差**不是噪声**——它与交易所、与夜盘档位严格单调相关，在整个回测期内方向恒定。

这是本用途下 ffill 最严重的后果，比不可成交信号更隐蔽：它不产生任何报错，只是让你的组合悄悄、稳定地偏向夜盘短的品种，然后你会把由此产生的收益或亏损归因到策略逻辑上。

## 4.3 对其他指标的污染

- **均线**：在填充段被拉平 → 产生虚假的"均线走平/粘合"形态
- **ATR / 真实波幅**：填充 bar 的 TR = 0 → ATR 被压低 → 若止损距离以 ATR 计，止损被压缩 → 回测中止损更少被触发 → **胜率虚高、单笔亏损虚低**
- **成交量类条件**：填充 bar 的 volume = 0，**永远满足"缩量"条件**。若你的入场条件包含"缩量回调后放量确认"，缩量腿会在填充段被大量虚假满足
- **相关系数**：一方冻结、一方波动 → 相关系数被人为拉向 0（见第 7 节，这直接影响你的并发门控）

## 4.4 与前视偏差的同构性

两者都是"回测产生了现实中不存在的收益"，区别只在错误从哪扇门进来：前视偏差从**索引**门进（用了未来信息），ffill 从**数据准备**门进（用了不存在的市场）。前者有大量工具检查，后者几乎没有，因为它伪装成一次无害的数据清洗。

## 4.5 检测

- `volume == 0` 的 bar 占比，**按品种 × 按时段**分组
- 持仓量不变的 bar 占比
- OHLC 四值全等 **且** volume = 0 的 bar 占比
- 逐分钟收益率零值占比，跨品种比较——若 G1 品种的零值占比比 G3 高出约 38 个百分点，直接指向 ffill

**注意区分**：真实的低流动性合约（远月）也会出现 volume = 0 的真实 bar。判定标准应是"**在该品种应有的 session 之外还出现了 bar**"，而不是简单看 volume 是否为 0。这需要一张 session 表，不能靠数据自身判断。

# 5. "只用日盘 9:00–15:00" 方案的完整评估

## 5.1 优点（针对本用途，比通常说的更实质）

- 所有商品品种共享同一时段 → 横截面从"四档不同步"降为单一时段
- **每交易日 225 根，全品种一致 → 反波动率的分钟标尺天然可比**。这是对本用途最实质的优点，第 4.2 节那张扭曲表整个消失
- 并发持仓门控可在统一时钟上定义，不存在"部分品种已收市"的中间状态
- 残留问题：10:15–10:30 小节休息仍是缺口（全品种同步，危害小）；中金所时段与商品不同【记忆-待核实，若涉及需单独查证】

## 5.2 代价一：夜盘没有消失，被压缩成 15:00 → 9:00 的跳空

9:00 的开盘价**已经包含整夜行情**。你不观测它，不等于不承担它。

**对本用途的具体后果**：你用 225 根日盘分钟收益率估计波动率，但持仓承担的是完整交易日（最多 555 分钟市场时间 + 跳空）的风险。夜盘越长的品种，被排除在测量之外的风险越多 → 波动率被低估越多 → **权重被高估越多**。

注意这与第 4.2 节 ffill 的偏差**方向相反**（ffill 高估夜盘**短**的品种，日盘截断高估夜盘**长**的品种）。两者不会互相抵消——它们是二选一的方案，各自带一个方向相反的结构性偏差。

**补救（关键，且便宜）**：把波动率估计移到**交易日频率**（结算价到结算价，或收盘价到收盘价）。日频收益率自动包含夜盘与跳空的全部方差，与 session 结构完全无关。

> **信息使用 ≠ 交易时段。** 你完全可以只在日盘下单，同时用全时段数据估计风险。这两个决策是正交的，很多实现把它们绑死了。

## 5.3 代价二：海外信息通道被剔除，且按品种分类

| 联动强度 | 品种 | 夜盘档位 | 剔除夜盘的代价 |
|---|---|---|---|
| 强（伦敦/COMEX/Brent 定价） | 黄金、白银、原油、低硫燃料油、国际铜 | 02:30 | **大**。夜盘是主要定价时段 |
| 强（LME 定价） | 铜、铝、锌、铅、镍、锡 | 01:00 | **大** |
| 中 | 棕榈油、豆类、橡胶、20号胶 | 23:00 / 02:30 | 中等 |
| 弱（国内供需主导） | 螺纹、热卷、玻璃、纯碱、焦煤焦炭、多数农产品 | 23:00 | **小** |
| **不适用** | 工业硅、多晶硅、碳酸锂、**铂、钯**、苹果、红枣 | **无夜盘** | 无——问题不存在 |

【档位与品种的完整映射请以各所公告或行情商时段表逐品种核对；上表分组为示例性质，个别品种可能已调整】

**必须点出的反例**：广期所 2025-11-27 上市的**铂、钯期货没有夜盘**，交易时间为 9:00–10:15 / 10:30–11:30 / 13:30–15:00。这两个品种与 NYMEX/伦敦铂钯强联动，却**制度上就不给你夜盘通道**——整夜的海外信息只能以 9:00 的跳空形式到达。

这个反例的含义：**"强联动品种需要夜盘"不是一个可以贯彻的原则，因为交易所并不按联动强度分配夜盘。** 你的品种池里已经存在"强联动但无夜盘"的品种，这说明跳空承接是必须处理的常态，而不是只用日盘才引入的特例。

**对本用途的横截面含义**：若品种池混合强联动与弱联动，"只用日盘"对不同品种的信息损失不同 → 又一个横截面上的不对称偏差。

## 5.4 代价三：夜盘无法管理仓位

- 若持仓过夜：夜盘风险照单全收，但止损在夜盘不执行。若 9:00 跳空穿过止损位，实际成交远差于止损价 → **回测中的单笔最大亏损被系统性低估** → R 倍数分布失真 → 你据以评估的胜率/赔率组合建立在错误的 R 上
- 若日内平仓（15:00 前全平）：**策略性质已改变**。持仓周期被截断为 ≤1 个日盘（225 分钟）；同时上期所/上期能源区分"平仓"与"平今"，平今手续费常显著更高，日内策略必须单独建模，否则实盘成本远超回测

## 5.5 对你这个配置的结论

**不要用"只用日盘"去解决对齐问题。** 它解决的是一个应该在索引层解决的问题，代价却是策略定义的改变。

具体执行顺序（按性价比排序）：

1. **先把波动率估计移到日频**（结算价到结算价）。这一步单独就消除了对齐问题对仓位分配层的**全部**影响——第 4.2 节的扭曲表、5.2 的截断偏差、2.1 的封板塌陷，三者同时被解决。成本近乎为零，不需要放弃任何时段
2. **然后按档位分组**（第 7 节），组内全时段，组间只在日频交互
3. **只有当你的策略本身就是日内、不持仓过夜时**，"只用日盘"才是一个自洽的选择——此时它不是简化，而是策略定义的一部分

反过来说：如果做完第 1 步之后你仍然觉得需要"只用日盘"来让代码跑通，那说明问题出在索引设计上，第 7 节应该能解决它。

# 6. 集合竞价 K 线的处理

## 6.1 性质

9:00 与 21:00 的撮合是**单次拍卖**，按最大成交量原则一次性产生一个价格和一个成交量，不是连续交易。这一笔在数据流中通常表现为一个体量异常大的成交。

自 2023-05-26 起，有夜盘品种在**日盘开盘前也有集合竞价**，但各所处理不同：上期所/上期能源/大商所新增 8:55–8:59 申报 + 8:59–9:00 撮合；**郑商所不新增集合竞价，只允许 8:55–8:59 撤单**。

**这意味着 9:00 这根 K 线在品种间结构不同**：上期所品种可能包含一笔拍卖成交，郑商所品种则是直接进入连续竞价。任何跨品种的"开盘成交量"比较在这根 bar 上不成立。

## 6.2 数据商处理不一致

| 处理方式 | 后果 |
|---|---|
| 并入第一根分钟 K 线 | 第一根 bar 成交量虚高（拍卖量 + 第一分钟连续交易量）→ **虚假放量** |
| 单独成一根（时间戳 8:59 或 9:00:00） | 面板上多出一根，与其他品种/其他数据源不对齐；每日 bar 数 226 而非 225 |
| 丢弃 | 你的"开盘价"可能与交易所公布的开盘价不一致（开盘价的官方定义就是集合竞价成交价） |

同一个数据商对不同交易所、不同历史时期的处理都可能不一致。**必须实测，不能读文档。**

## 6.3 对信号的影响

- **成交量条件**：第一根 bar 的成交量不可用于"放量确认"。若入场逻辑含"放量突破"，开盘那根会被虚假触发；若含"缩量"腿，开盘那根会被虚假排除
- **开盘触发类信号**：若信号在 9:00 触发并假设以 9:00 开盘价成交——**这是不可能的**。开盘价是集合竞价的产物，撮合发生在 8:59–9:00 且该阶段不接受申报。你能成交的最早价格是 9:00 之后连续竞价的第一笔

## 6.4 建议处理

1. **识别**：对每个品种，计算 `第一根 bar 成交量 / 其后 5 根成交量的中位数`。若该比值在品种间差异巨大，说明数据商处理不一致
2. **标记**：给每个 session 的第一根 bar 打 `is_auction_bar = True`
3. **成交量类条件**：一律排除 `is_auction_bar` 的 bar
4. **执行层**：最早可成交时间设为 session 开始后的**第 2 根** bar（保守），或第 1 根 bar 的 close（若你接受以第一分钟收盘价成交的假设）。**不要用第一根 bar 的 open 成交**
5. **一致性**：全品种同一规则。若对上期所品种排除、对郑商所品种不排除，就在横截面上引入了新的不对称

# 7. 实施建议（针对本用途）

## 7.1 三层索引设计

| 层 | 索引 | 缺失值处理 |
|---|---|---|
| 信号/指标层 | `(instrument, trading_date, session_id, bar_seq)` | 不存在缺失——每品种只有自己真实存在的 bar |
| 组合状态层 | 全局事件队列，按 `(t_abs, instrument)` 排序 | 不存在缺失——事件流只包含真实发生的事件 |
| 仓位/绩效层 | `trading_date` | 品种当日无交易则退出当日横截面（不填充） |

**`t_abs` 的定义**（单调、跨午夜安全、节后首日自动正确）：

```
t_abs = trading_date_ordinal * 1440 + minutes_since_2100_of_prev_day
```

以交易日 T 的 21:00（T−1 自然日）为 offset 0：

| 墙钟 | offset |
|---|---|
| 21:00 | 0 |
| 23:00 | 120 |
| 次日 01:00 | 240 |
| 次日 02:30 | 330 |
| 09:00 | 720 |
| 15:00 | 1080 |

节后第一个交易日没有前置夜盘，offset 自然从 720 开始——不需要特判，只需要日历表告诉你该日 `has_night_session = False`。

## 7.2 session 表（本方案的唯一真值源）

| session_id | 时段 | 分钟数 | 适用组 |
|---|---|---|---|
| N1 | 21:00–23:00 | 120 | G1, G2, G3 |
| N2 | 23:00–01:00 | 120 | G2, G3 |
| N3 | 01:00–02:30 | 90 | G3 |
| D1 | 09:00–10:15 | 75 | 全部 |
| D2 | 10:30–11:30 | 60 | 全部 |
| D3 | 13:30–15:00 | 90 | 全部 |

把夜盘拆成 N1/N2/N3 的用处是让四个档位组成为**前缀关系**：G0 = {D1,D2,D3}；G1 = G0 ∪ {N1}；G2 = G1 ∪ {N2}；G3 = G2 ∪ {N3}。任意时刻"哪些品种活着"由此一目了然。

**但要注意**：对 G3 品种而言 N1/N2/N3 之间**没有休息**，是连续的 330 分钟。因此**指标计算时夜盘应视为一个 session**（该品种自 21:00 到自己的收市），N1/N2/N3 的拆分只用于面板分组判断，不用于指标窗口重置。混淆这两者会在 23:00 和 01:00 制造出不存在的段边界。

## 7.3 缺失值：保留 NaN，绝不填充

- 信号函数对 NaN 输入必须返回"无信号"，而不是"沿用前一信号"
- **不要用"数据是否为 NaN"判断可否交易**。数据可能因供应商问题缺失，而市场当时是开着的
- 执行层维护一个**独立于行情数据**的判定：

```
tradable(instrument, t) =
      在交易日历中 t 属于交易日
  AND t 落在该品种的 session 表内
  AND NOT is_limit_locked(instrument, t)
  AND NOT is_auction_bar(instrument, t)
```

这个函数由交易日历 + session 表 + 涨跌停状态生成，**与行情数据分离**。这样即使数据层出问题，执行层也不会放行。信号层与执行层因此使用不同索引——这不是冗余，是隔离。

## 7.4 反波动率仓位的具体处理

**不要**用"各品种自己的分钟收益率 std × sqrt(自己的 bar 数)"跨品种比较。两个独立的问题会同时发生：

1. bar 数不同（225 / 345 / 465 / 555），标准化系数必须逐品种正确
2. **即使系数正确，日内波动率本身有强周期性**——开盘高、午间低、夜盘开盘再次抬升。而不同档位品种的 session 构成不同，"平均一分钟"的含义因此不同。这一点有实证文献支撑（Andersen & Bollerslev 1997，来源见文末）

**建议**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **首选** | 用交易日频收益率估计波动率（结算价到结算价） | 响应慢（日更）；结算价是 VWAP，比收盘价平滑，会略微低估真实波动——但**跨品种一致地**低估，不破坏相对权重 |
| 次选 | 分钟数据，但按各品种实际 bar 数标准化，且明确声明估计的是"每交易日波动率" | 仍受日内周期性影响；封板日会塌陷 |
| 必加 | 权重上限 + 波动率下限（floor） | 防止封板品种权重发散 |

结算价而非收盘价的另一个好处：结算价是全日成交量加权均价，不可被尾盘单笔操纵，作为风险标尺比收盘价稳定。

**这一步是整份文档中性价比最高的一条**：它把仓位分配层从时间对齐问题里彻底摘出去，代价只是响应频率从分钟降到日。而反波动率权重本来也不该分钟级抖动。

## 7.5 并发持仓门控的具体处理

门控状态在**事件队列**上更新，不在固定时间网格上。两个必须处理的边界情况：

**边界一：23:00 后 G1 品种仍持仓**
螺纹 23:00 收市，你仍持有它。此时黄金在 23:30 触发新信号，门控问"当前有几个持仓"。

正确答案：**螺纹计入持仓数**。这是真实的市场状态——你确实持有它，只是无法调整它。若门控把"无新数据"当作"无持仓"，持仓数会在 23:00 虚假归零，导致门控在夜盘后半段完全失效，回测里出现现实中不会发生的集中开仓。

**边界二：相关系数在 23:00 后无法更新**
若门控依赖跨品种相关系数（相关性门控/波动率预算），23:00 后 G1 品种没有新数据。

- **错误做法**：用 ffill 的价格重算相关系数。一方恒定不动、一方在波动 → 相关系数被人为拉向 0 → 门控误判为"不相关，可以开仓"→ **在真实相关性最高的时刻（海外市场共同驱动）放开了敞口**
- **正确做法**：把该品种对的相关系数**冻结**在其最后一次共同更新的时刻，并标记为 stale。或者，更简单：相关系数本来就该用日频数据估计（同 7.4），此时这个问题不存在

这两条与 7.4 指向同一个结论：**组合层的量应当在日频计算，只在分钟层做单品种信号与执行。** 把组合层的量下沉到分钟层，才是需要面板对齐的根源。

## 7.6 跨品种分组

按夜盘档位分四组（G0/G1/G2/G3）。**组内**成员时段完全一致，可以做时间戳对齐、可以直接横截面比较分钟量。**组间不强行对齐**——跨组的交互只发生在交易日频率上。

若你确实需要分钟级的跨组量（例如全组合的实时敞口），用事件队列的"最后已知状态"，并**显式标记每个品种状态的时效**（stale 与否），而不是把它伪装成同步数据。

## 7.7 若用途或频率改变，答案如何改变

| 变更 | 答案如何变 |
|---|---|
| → **跨品种价差套利** | 3.2 inner join 变为**必须**。分组无意义（价差两腿必须真同步）；只能在双腿都在交易时建/平仓；组间配对基本不可行（G0 与 G3 的价差在夜盘只有一条腿） |
| → **固定时间截面排序** | 只需选一个所有品种都在交易的采样时刻（必落在日盘内，如 14:55）。第 2–4 节的大部分内容不适用，问题退化为"确保采样时刻数据真实存在" |
| → **日线频率** | 本文退化为只剩第 1 节。第 2、3、4、6 节基本不适用；第 5 节变为纯粹的策略问题 |
| → **5 分钟** | 结构问题完全相同，只是 bar 数变为 45 / 69 / 93 / 111（75、60、90 均可被 5 整除）。所有结论不变 |
| → **30 分钟或 1 小时** | **新增一个更严重的问题**：75 分钟不能被 30 或 60 整除。重采样边界的定义（按 session 内序号切 / 按墙钟整点切 / 跨小节休息连续切）本身就有多种互不兼容的口径，不同数据商结果不同。这个错误发生在你做任何对齐之前，必须先解决 |
| → 单品种 | 第 3 节的横截面顾虑全部消失，只剩第 1、2、4、6 节 |

# 8. 验证清单

每项：**检查什么 / 通过标准 / 不通过说明哪里错了**。建议按顺序执行，C2 不过就不必往下做。

## C1 每交易日 bar 数

- **检查**：按 `(instrument, trading_date)` 统计 1 分钟 bar 数
- **通过标准**：G0 = 225；G1 = 345；G2 = 465；G3 = 555（±1，取决于集合竞价 bar 是否单列，但**同一品种必须始终一致**）
- **不通过**：多于应有 → 存在填充，或集合竞价单独成 bar；少于应有 → 数据缺失或当日临时休市；**同一品种在不同交易日数值跳动 → 交易日边界错误**

## C2 分钟聚合日线 vs 交易所公布收盘价【最强单一检验】

- **检查**：按交易日分组取最后一根 bar 的 close，与交易所官网公布的当日收盘价逐日比对
- **通过标准**：完全相等（到最小变动价位），全样本无例外
- **不通过**：
  - 你的值等于 23:00/01:00/02:30 的价格 → **按自然日切了交易日**
  - 你的值等于前一日的值 → 时区错误或 bar 标签左右偏移
  - 只在部分品种上错 → 按夜盘档位分组检查，问题在夜盘归属

**先跑这一条。** 交易日边界错误、时区错误、标签偏移三类问题会在这里同时暴露，且不可能被侥幸通过。在这一条通过之前，写任何策略代码都是浪费。

## C3 结算价对账

- **检查**：按交易日对全部 bar 做成交量加权均价，与交易所公布结算价比对
- **通过标准**：接近但**不会完全相等**（分钟聚合损失了分钟内的价量分布），相对偏差在数个最小变动价位以内
- **不通过**：偏差显著 → VWAP 覆盖的时段不对，即夜盘 bar 归属错误。注意 C2 通过而 C3 不通过是可能的：收盘价只依赖最后一根 bar，结算价依赖全部 bar

## C4 零成交量 bar 占比

- **检查**：按 `(instrument, session_id)` 统计 `volume == 0` 的占比
- **通过标准**：主力近月合约应接近 0
- **不通过**：**若某品种在其收市后的时段存在 bar → ffill**（这是判定填充的直接证据）；若集中在特定 session → 检查该品种该时段是否本就无交易

## C5 零收益率 bar 占比的跨品种比较

- **检查**：按品种统计 `return == 0` 的 bar 占比
- **通过标准**：占比应与该品种流动性一致，且**不应与夜盘档位单调相关**
- **不通过**：若 G1 品种的零收益占比比 G3 高出约 38 个百分点、G0 高出约 60 个百分点 → 面板被扩展并填充，且第 4.2 节的权重扭曲已经发生

## C6 节假日前一交易日无夜盘

- **检查**：从交易日历取"节假日前最后一个交易日"，检查该日 bar 数与时间范围
- **通过标准**：**全品种** 225 根，无 21:00 之后的 bar
- **不通过**：存在夜盘 bar → 数据源填充了不存在的时段，或你的交易日历没有 `has_night_session` 字段

## C7 节假日后第一个交易日

- **检查**：该交易日第一根 bar 的墙钟时间
- **通过标准**：应为 9:00（或 8:59 的集合竞价 bar），**不应存在 21:00 的 bar**
- **不通过**：存在 21:00 bar → 你用了"前一交易日 21:00"的通式推算交易日起点，而没查日历

## C8 NaN 分布与夜盘档位一致性

- **检查**：在跨品种面板上，对每个时间戳统计有值的品种集合
- **通过标准**：9:00–15:00 应为全集；23:00 后 ⊆ G2∪G3；01:00 后 ⊆ G3；10:15–10:30 应为空集
- **不通过**：23:30 存在 G1 品种的值 → 填充；10:20 存在任何值 → 小节休息被填充；日盘时段存在 NaN → 真实数据缺失，需回补而非填充

## C9 封板检测

- **检查**：`|close − 涨停价| < 0.5 tick` 或 `|close − 跌停价| < 0.5 tick`，且成交量显著低于当日中位数。**涨跌停价须用昨结算价计算，不是昨收盘价**
- **通过标准**：这些 bar 被标记为 `tradable = False`，但**保留在数据中**并参与指标计算
- **不通过**：若被删除 → 价格序列出现虚假跳空；若未标记 → 回测在封板期成交，且该品种波动率塌陷、反波动率权重发散

## C10 波动率标尺可比性

- **检查**：对每个品种，比较两个估计——(a) 分钟收益率 std × sqrt(该品种实际 bar 数)，(b) 日频收益率 std
- **通过标准**：比值 (a)/(b) 在同一量级（因日内/隔夜波动结构不同，偏离 1 是正常的）
- **不通过**：**关键在于比值是否按夜盘档位系统性分组**。若 G1 品种的比值系统性低于 G3，说明 bar 数标准化错误或存在填充。这一条直接检验第 4.2 节那张扭曲表是否已经发生在你的数据上

## C11 集合竞价 bar 识别

- **检查**：`每 session 第一根 bar 的成交量 / 其后 5 根的中位数`，按品种统计
- **通过标准**：该比值在品种间大致同量级
- **不通过**：某些品种远高于其他品种 → 数据商对这些品种把拍卖量并入了第一根 bar，需统一在成交量条件中排除

## C12 事件序确定性【本用途特有】

- **检查**：把所有品种展开成全局事件流，同一 `t_abs` 上必然存在多个品种的事件。用不同的输入顺序（如打乱品种列表顺序）重跑回测
- **通过标准**：**结果完全一致**（逐笔成交、逐日净值，不只是最终收益）
- **不通过**：结果不同 → 并发事件的处理顺序未定义 → 并发持仓门控的结果不可复现，回测结论无意义。修法：在排序键中加入确定的二级键（如品种代码字典序）

## C13 门控在跨档位时刻的行为【本用途特有】

- **检查**：在 23:00 与 01:00 前后，打印持仓门控的完整状态（持仓数、各品种状态、相关系数及其时效标记）
- **通过标准**：
  - G1 品种在 23:00 后状态为"持仓中 / 不可交易"，**计入持仓数**
  - G1 品种在 23:00 后**不产生任何新信号**
  - 涉及 G1 的相关系数被标记为 stale 且**数值冻结**
- **不通过**：
  - 持仓数在 23:00 下降 → 门控把"无数据"误判为"无持仓"
  - G1 品种在 23:00 后产生信号 → 填充
  - 相关系数在 23:00 后仍在变化且趋向 0 → 用填充价格重算了相关性，门控会在最危险的时刻放开敞口
