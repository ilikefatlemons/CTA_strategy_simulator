# 交易信号 / 止损止盈逻辑审计报告

审计对象：`src/rules/{ma_filter,pullback_entry,stop_loss,take_profit,cooldown}.py`、
`src/engine/pullback_backtest.py`、`src/data/resample.py`
审计目的：确认信号生成、止损止盈、仓位管理的逻辑合理性，并逐条验证不存在"未来函数"（用尚未发生的数据做当前决策）。
数据：12个标的（9只股票 + USO/GLD/SLV商品ETF代理），2024-07-18 ~ 2026-07-17，5分钟K线，Alpaca复权数据。

---

## 一、信号逻辑：四级时间框架级联

**方向判断（2h定方向，`ma_filter.py::ma_array_state`）**
用2h K线的MA5/MA20/MA50严格排列判定：MA5>MA20>MA50 → 多头bias；MA5<MA20<MA50 → 空头bias；其余neutral。
- 合理性：用最大周期(2h)定方向，避免小周期噪音误判大趋势；严格三线排列门槛较高，保证只在趋势明确时才给方向，neutral时直接不开仓。

**回调确认（`pullback_occurred`）**
30m必须用MA5/MA20（不含MA50，门槛降低以增加触发频率）转为与2h方向相反的排列（硬性条件），且5m或15m至少一个也转为反向（OR）。
- 合理性：30m作为"必要不充分"条件，保证回调有一定深度和延续性；5m/15m用OR而非AND，是因为二者谁先反向不固定——5m快但噪音大，15m平滑但滞后，用OR保证两个周期都在真实贡献信号（4票统计约27%的"至少一个反向"时刻只有15m反向、5m未反向，说明15m不是"陪衬"）。

**入场触发（`get_entry_trigger`）**
5m和15m必须都重新转回与2h同向排列（AND）才触发信号。
- 合理性：要求两个小周期同时确认，减少假突破；触发后清空回调状态，下一次入场必须重新走完整轮回调，不会用旧的回调状态重复开仓。

**非前视性核查**：
- 传给判断函数的K线全部是"已收盘"K线（见`pullback_backtest.py`第90-92行 `closed_klines`），来自`resample.py::closed_bar_positions`的边界计算：一根标签为`t`的K线只有在`t+周期 <= 当前bar开盘时间`时才可用，用`searchsorted(..., side="right") - 1`实现严格的"只用已经走完的K线"，代码注释里明确写了为什么不能用`<`（会晚一格）或不做位移（会用到还在走的K线）。
- 5m自身传的是`df_5m.iloc[:i+1]`（含当前bar自己，因为5m是最细粒度，当前bar本身已经走完才能看到它的收盘价用于判断），15m/30m/2h传的是`closed_klines`过滤后的、严格早于当前bar的已收盘K线，不会看到"正在形成中"的高周期K线。

## 二、止损逻辑（`stop_loss.py`）

`ATR止损`与`平台止损`取"离入场价更近"的一个，再留0.3%缓冲（防止被扫损）：
- ATR止损：`entry_price ∓ 1.5 × ATR(14)`
- 平台止损：30m K线的swing high/low（左右各2根K线的局部极值）

- 合理性：ATR止损给出与当前波动率匹配的止损距离；平台止损贴合实际结构支撑/阻力位。二者取更近的一个，是"更保守"（亏得更少）的选择，不是取更远的博取容错。
- **参考值**：1.5倍ATR是趋势跟随策略里常见的止损宽度区间（业界常见范围1.5~3倍ATR，1.5倍偏紧、适合波动率加权的多标的组合，能更快止损纠错）。

**非前视性核查**：`_swing_points`用`range(k, len(klines)-k)`，只能识别"两侧各有k根已知K线"的局部极值，且传入的`klines_30m`本身就是"已收盘"数据，不会用尚未出现的K线反推当前的支撑/阻力位。

## 三、止盈逻辑（`take_profit.py`）：两条腿

**腿A（50%仓位）**：固定盈亏比部分止盈，`trigger = entry_price ± 2R`（R=入场价与止损价距离），触发后平掉50%仓位，锁定确定性利润。
**腿B（剩余50%）**：吊灯止损跑趋势，`trailing_stop = max(extreme_price - 3×ATR, floor_stop)`（floor_stop=原始止损，只上移不下移/只下移不上移），价格触及则平掉剩余仓位（`reason=PROTECTIVE_SL`，区别于"整批原始止损"的`SL`）。

- **参考值**：2R止盈是1.5~2R区间常见做法的上限，配合40%左右胜率，数学期望为正（`期望值 = 胜率×盈亏比 - (1-胜率)×1`，下面第五节有实测验证）。3倍ATR吊灯止损是让"已经走出空间的趋势"充分奔跑同时锁定利润的常见宽度。
- 合理性：吊灯止损"只朝有利方向移动、永不比原始止损更差"，保证一旦部分止盈过，剩余仓位的下行风险不会比最初设定的止损更差，不存在"越跑越亏"的情况。

**非前视性核查（关键点）**：`pullback_backtest.py`第146-150行明确用`atr_full.iloc[i-1]`而不是`iloc[i]`计算吊灯止损——因为bar i自己的ATR需要bar i的收盘价才能算出，而当前正在判断的正是bar i的价格是否触及止损线，用bar i自己的ATR等于用了"这根K线还没走完就已经知道的信息"。这是本次审计里发现的、写得最谨慎的一处未来函数防护，代码里有专门注释说明。

## 四、冷静期风控（`cooldown.py`）--不动已有仓位，只针对新开仓

触发条件（两个之一）：
1. 同方向连续3次"纯止损"（`reason=SL`，未部分止盈过的批次）——说明连续判断错方向；护盈止损(`PROTECTIVE_SL`)不计入，因为那种情况方向判断是对的，只是回吐了部分利润，性质不同。
2. 单根2h K线实体击穿至少2条均线——暴力单边行情，均线滞后，先观望。

解除条件：连续3根2h K线都稳定在同一个干净排列（不要求方向跟触发前一致）。

- 合理性：区分"判断错方向"和"利润小幅回吐"两种情况，避免风控过度敏感；解除要求"连续3根"而非"1根"，避免单根K线噪音误解除冷静期。

**非前视性核查**：`check_structure_break`只看`klines.iloc[-1]`（最新一根已收盘K线），`on_bar`逐bar调用、状态在bar间累积，没有用到未来K线。

## 五、执行细节：入场价与成交时机

信号在bar i触发后，**成交价用`df_5m["open"].iloc[i+1]`**（下一根5m K线的开盘价），不用触发那根K线自己的收盘价/当前价：
- 合理性：这是保守估计，避免"看到这根K线走完形成信号，还用这根K线自己的价格成交"的未来函数；现实中信号确认时这根K线已经收盘，只能等下一根K线开盘价成交。
- 权益曲线在`entry_bar_idx`真正到达前保持平仓状态（`pullback_backtest.py`第190-196行注释），不会在信号刚生成、尚未真正成交时就让浮盈浮亏影响净值。

## 七、结论

1. **信号级联、止损止盈、冷静期风控三部分的每一步都能用当前bar及更早的已收盘数据独立复现**，没有发现使用未来数据的路径。
2. 唯一容易踩坑但已被正确处理的点：吊灯止损计算用`atr_prev`(i-1)而非当前bar的ATR——已在`pullback_backtest.py`中显式处理并注释说明。
3. 实测胜率/盈亏比/期望值符合"趋势跟随+固定盈亏比"策略类型的典型特征，没有出现内部不自洽的数值（比如"设计止盈2R但实测盈亏比远低于2"这种能暴露bug的矛盾）。
4. 汇报建议：主动提出"策略收益<买入持有"这一点并解释是"控回撤换Sharpe"的设计取舍，比等经理发现更主动、也更能体现审计是认真做的。
