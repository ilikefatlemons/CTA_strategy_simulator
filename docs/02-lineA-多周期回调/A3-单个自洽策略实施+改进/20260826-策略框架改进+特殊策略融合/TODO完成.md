### 先纠正一个前提

**第一稿就已经是对的。** `git show 1a5a6da` 里极值折入在第 396 行、出场测试在 375 行——折入本来就排在测试之后，从没用当根的 high/low 去算过线。第一稿的问题是**分辨率**（15m 粒度看不见箱内路径），不是**滞后**。TODO 2 修的是前者。

### 机械凭据（`test_吊灯的极值严格滞后一根_不含本根的high_low`）

```
滞后版（现行）   292/292 笔与引擎逐笔一致（下标、理由精确相等，价格 1e-9 相对容差）
含本根版（错排）   5/292 笔不一致          <- 空真守卫，必须 > 0

```

**偏差有方向，不是噪声。**含本根 = 先用本根 high 抬高吊灯、再拿本根 low 去撞它，凭空造出一笔真实市场里不可能发生的、更早的出场。所以长期看它会系统性地高估「吊灯及时锁利」的能力。

截断法抓不到这条：截断法验的是「有没有读到未来的 bar」，而这里的错误是「同一根 bar 内部把顺序搞反了」——那样的引擎在截断法下照样全绿。两条测试互补，缺一不可。

### 完整逻辑链（伪代码）

驱动周期 = 1m。`i` 是驱动 bar 的下标。**信号层不跟着它走**：大周期读 2h 自己的已收盘 bar，回调与两个开关读 15m 的，30m 只出 ATR。

```
入场那一刻（bar e，成交价 = open[e]）:
    ATR₀      ← ATR(14, 30m)[ 截至 e 最后一根已收盘的 30m ]      # 冻结，整笔不再变
    固定止损位 ← 入场价 ∓ 1.5 × ATR₀                              # 冻结，整笔不再变
    持仓极值   ← 入场价                                           # 之后逐根累积

逐根 i（i 从 e 开始）:

    ── 出场块 ────────────────────────────────────────────────
    if 持仓中 and 可成交[i] and i > e:          # 竞价根不成交；本根开的仓本根不平

        # 1. 吊灯用的 ATR
        if 止盈_ATR随动:
            吊ATR ← ATR(14, 30m)[ closed_pos_30m[i] ]   # 截至本根**已收盘**的那根
        else:                                            # 不是「包含本根」的那根
            吊ATR ← ATR₀                                 # 后者没收盘，用它=未来函数

        # 2. 原始吊灯线  —— 极值只到 i-1，本根的 high/low 还没折进来
        原线 ← 持仓极值 ∓ 3 × 吊ATR

        # 3. 止盈阀门：线差于入场价就不许用它出场
        受阻 ← 止盈_不得差于入场价 and (原线 差于 入场价)
        有效线 ← 固定止损位            if 受阻
                 取更优(原线, 固定止损位) otherwise      # 多头取大 / 空头取小

        # 4. 触发判定 —— 这里才第一次读本根的 low/high，读的是**事件本身**
        if (多头 and low[i] ≤ 有效线) or (空头 and high[i] ≥ 有效线):
            成交价 ← 跳空补价(有效线, open[i])          # 跳空穿过时按 open 成交
            理由   ← SL     if 有效线 == 固定止损位      # 含「受阻」那一支
                     TRAIL  otherwise
            平仓; 记一笔; 退出本根

    ── 极值折入 ──────────────────────────────────────────────
    # **必须排在出场测试之后**，并带持仓守卫（上面可能刚平掉）
    if 持仓中 and 可成交[i] and i ≥ e:
        持仓极值 ← 取更优(持仓极值, high[i] 或 low[i])   # 只影响 i+1 及以后
```

**三条顺序不能动：**

1. **极值折入排在出场测试之后。** 这是全库唯一结构上危险的一步（三个引擎同形）。反过来就是本节开头量到的那 5 笔假出场。
2. **入场排在出场之前。** 信号读的是 i-1 及更早的已收盘 bar，在 bar i 开盘那一刻就已知；实盘就是那一刻发单，天然早于本根盘中才发生的触损。
3. **出场块的守卫是 `i > e`，极值折入的守卫是 `i ≥ e`。** 入场那一根不测出场（`一根bar只做一个动作`），但它的 high/low 照样进极值。这两个守卫不同，`_独立重算出场` 曾漏掉这一折，328 笔里 1 笔露馅。

**本根数据只在两个地方被读：**`low[i]/high[i]` 做触发判定（事件本身，不是预测），`open[i]` 做跳空补价（成交那一刻已知）。**决定线在哪的所有输入都截至 i-1。**

阀门管的是**线**，成交价可以跳空穿过它：

```
2026-06-02 22:31 空  入场 968.9805
  出场 2026-06-04 21:00  线 968.5056（≤ 入场，阀门满足）  成交 971.7027  净 −0.281%
2026-07-01 01:16 空  入场 868.1391
  出场 2026-07-01 21:00  线 864.0346（≤ 入场，阀门满足）  成交 868.9479  净 −0.093%
```

两笔都 `跳空成交=True`，成交价比线差了 3.20 / 4.91。价格跳过止损位时按线成交是不诚实的，`gap_filled` 按 bar 的 open 补价——所以**阀门无法保证成交价不亏，只能保证线不亏**。这是真实市场行为，不是 bug。

### 竞价根完全退出成交判定

竞价根在入场侧本就被挡（「一个撮合价、零振幅、成交中位 99 手，按它成交是假的」）。这一轮把它从**出场**与**极值折入**里也挡掉了——原则是：**凡是「会导致按这个价成交、或因这个价而改变成交」的地方一律排除。**

**出场**：挡掉后止损顺延到下一根真实交易分钟（AU 上是 21:01）。注意竞价价与 21:01 的 open **并不相等**，所以这不只是「把箭头挪一下」，成交价确实变了：

```
2026-06-02  21:00 @971.7027  ->  21:01 @971.8802   （略差）
2026-07-01  21:00 @868.9479  ->  21:01 @868.8295   （略好）
```

**极值折入**：这条最容易漏，也最要紧。竞价根是零振幅的单点，折进持仓极值会把吊灯线拉走、进而改变真实出场。实测 AU 上 **91 个落在持仓区间内的竞价根里有 24 个（26%）真的刷新了极值**，最大一次把极值推了 **4.95**：

```
2025-09-04 22:46 多   09-05 21:00 竞价根   极值 816.9065 -> 821.8564  (+4.95)
2025-09-04 22:46 多   09-08 21:00 竞价根   极值 824.8702 -> 828.3032  (+3.43)
```

**逐根 mark-to-market 不在此列**：它只记账、不产生成交，而竞价价是那一刻交易所公布的唯一价格，按它记账是诚实的。

**收益影响极小**（+25.17% → +25.16%），因为推高的极值让吊灯变紧、而阀门本就挡掉大部分，真实 bar 很快又会把极值推得更远。**这个修正的价值在原理不在收益**——不该让一个不可成交的撮合价去移动一条真实的止损线。

`可成交` 是 `回测结果` 的一个字段（出场与极值折入都受它挡）。竞价根上出场块整块不跑，所以三条止损线在那些根上都不写，引擎与图层两处测试都把这条钉死了；`_独立重算出场` 的四处极值折入统一收进一个 `折()` 里，与引擎同一个守卫。

> **仍未解决**：跳空穿过止损位时成交价仍可能亏。要做到 strictly「TP 绝不亏损」，得改成
> 跳空时不走 TP、只能等 SL 或后续的 TP —— 那是另一个语义，留待后续。

**其二：阀门开着为什么 `吊灯盈` 从 40 掉到 39？——不是阀门挡的，是交易序列整个变了。**

按定义，受阻 ⟺ 吊灯线差于入场价 ⟺ 若在此出场必亏，所以**阀门不可能直接挡掉一笔盈利的吊灯出场**。实测印证：101 笔共有交易里，「关阀门时是盈利吊灯、开阀门后不再是」的有 **0 笔**。

差异全部来自序列发散：开阀门 104 笔 / 关阀门 113 笔，两边共有 101 笔，只在开的 3 笔、只在关的 12 笔。挡掉一次出场会改变持仓占用，后面的入场机会跟着全变。**所以这两组的笔数级指标不能一一对应地读。**

### 前端两处配套

1. **两条止损线只画在驱动周期那一格**，pill 改名 `止损/吊灯线(1m)`。粗周期上每个箱只能留一个值（箱末），一根 30m 里若有两笔交易，前一笔的平仓价位会被后一笔整个盖掉——那是**画错**不是粗糙。判据提成 `该画止损线()`，单独有测试钉。
2. **被阀门挡住的根换深绿**（`#14521a`），不是不画。新加 `吊灯受阻线`，值是吊灯那条的子集，**建在吊灯之后**所以点位重合时画在上面；吊灯那条保留全部值，图例读它才不会变空。引擎新增逐根 bool 数组 `吊灯受阻`。
3. **止损图例也只建在驱动格。** 别的格子根本没有止损线数据，建了图例也永远只显示「未开仓」——那不是信息，是噪声。没有 `stopLegend` 的格子在 `注册瓦片` 里导出 `null`，`applyPanes` 相应加了空守卫。
4. **光标停在深绿点上时，图例写成 `吊灯（禁用）: 971.88`**——「（禁用）」缀在**标签**后面，不是数值后面。缀在最后会读成「这个价位被禁用」，而实际含义是「吊灯这一条本根不生效」。两条渲染路径（悬停本格的 `_止损图例`、悬停别格的广播 `extras`）文案必须逐字一致，否则同一根 K 线在不同格上读数不同。为此给 `lwc_helpers` 的 extras 加了一对可选键 `flag_line` / `flag_text`：另一条 series 在该时刻有值就把文案缀在标签后面。与既有的 `empty` / `sign` 同一形状，向后兼容。

### 连带改的不变量

`止损线 = max(固定止损线, 吊灯原线)` **多了一支**：受阻的根上有效止损退回固定止损。测试分成「通过阀门」与「受阻」两段断言并带空真守卫。`_独立重算出场` 也补上了阀门。
