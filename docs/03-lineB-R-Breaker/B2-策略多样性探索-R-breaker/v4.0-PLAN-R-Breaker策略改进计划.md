## Context：v3.0 交到手上的是什么

两个**完全独立**的 R-Breaker 策略，共用数据层与执行纪律，互不干涉：

| | 突破 | 反转 |
|---|---|---|
| 引擎 | `src/engine/rbreaker_backtest.py` | `src/engine/rbreaker_reversal_backtest.py` |
| 入场 | `high[i−1] > Bbreak` / `low[i−1] < Sbreak` | 武装（触及 Ssetup/Bsetup）+ 触发（破 Senter/Benter） |
| 出场 | **只有**追踪止损 + 时段末强平 | 同左 |
| 一年成交（59 品种） | 7,063 | 5,005 |
| 净收益中位 | −1.48% | +1.23% |
| 止损 : 收盘平仓 | 2,016 : 5,047 | 1,308 : 3,697 |

**逐品种净收益相关系数 +0.145** —— 两者近乎正交，这是把它们并排放的唯一硬理由。

五个已知缺口，正是本文的五节：

1. 日夜分时段是一个**未经隔离检验**的假设；
2. **涨跌停板完全没有实现，也没有数据** —— 板上能开仓，止损在封板时仍按正常撮合；
3. 六线公式仍是昨日单日 H/L/C 的点估计，未用上 1 分钟数据；
4. 突破入场对**跳空越线**毫无防护，实际风险随跳空幅度 1:1 膨胀且无上限；
5. 突破与反转还只是两个并排的策略，没有合成。

# §0 标准化测试规范（STD-TEST）

## 0.1 两类测试，必须分开记账

| | **A 类 · 市场事实测量** | **B 类 · 策略配置选择** |
|---|---|---|
| 输出 | 一个关于市场或现有实现的分布 | 两个配置的**配对差值**分布 |
| 是否下判据 | **否**，只测量 | **是**，判据必须预注册 |
| 多重检验预算 | **不消耗** | **消耗** |
| 数据窗口 | **全历史**（拿最大 n） | 训练窗口 + 留出集 |
| 过拟合风险 | 无（不做选择就无从过拟合） | 有 |

**核心纪律：每一个 B 类测试之前，必须先有一个 A 类测试证明它要修的问题真实存在。**
不为一个没被测量过的问题做 A/B —— 那是把噪声当成 bug 修。本文五节里，A 类占多数，这是刻意的。

## 0.2 测试窗口分层

| 用途 | 窗口 | 交易日数（量级） |
|---|---|---|
| A 类测量 | 2010-01-04 ~ 2026-07-29（全历史） | RB 4,017 |
| B 类训练 | 2023-01-01 ~ 2025-06-30 | ~600 |
| **B 类留出（锁死）** | 2025-07-01 ~ 2026-07-29 | ~258 |

留出集**只在最终定稿时开封一次**。它与 v3.0 已发布的实测表是同一段数据 —— 这意味着 v3.0 那张 59×5×2 的表**已经污染了这段数据一次**。所以留出集的正确用法是：只用来确认最终方案的符号与量级，不用来做任何选择。这一条必须诚实记在案。

## 0.3 测试模板（每个测试按此写满，九个字段不得空缺）

```
TEST-<编号>  <名称>                                   [A 类 | B 类]
─────────────────────────────────────────────────────────────
问题      一句可证伪的陈述
观测单位  一行 = 什么
总体/窗口 品种池 × 日期区间 × 样本过滤
统计量    每单位算出的标量（给公式）
分层      分层键；每一层单独报 n
配对      配在什么键上（B 类必须配对）
输出      ① 直方图 / ECDF
          ② 分位数表 p1 · p5 · p25 · p50 · p75 · p95 · p99
          ③ mean ± 块 bootstrap 95% CI
          ④ n
n 口径    n_逐品种（中位 / 范围） · n_汇总 · n_有效
判据      预注册阈值（A 类写「无，仅测量」）
功效      该 n 下可检出的最小效应
```

## 0.4 六条全局规则

1. **每张分布图必须标 n**；分层图的每一层单独标 n。
2. **`n < 30` 的分层：只展示，禁止据其决策。** 图上标红。
3. **跨品种汇总的置信区间一律用按 `trading_date` 的平稳块 bootstrap。** 同一天 59 个品种共享宏观冲击，不独立；朴素地把 n 当成「总笔数」会把有效样本量夸大一个数量级。重采样的单位是**整个交易日**（该日全部品种一起进出），不是单笔交易。现成的分组函数是 `src/performance/sharpe.py:52-67` 的 `session_returns()`，它已经按 `trading_date` 分组，口径天然一致。
4. **B 类必须配对**，报 Δ 的分布，不报两个边际分布。配对键按测试性质取 symbol / session / trade。
5. **B 类判据事先写死**，不得看到结果再定阈值。
6. **功效底线**（配对检验，α=.05，power=.8）：

   | 想检出的效应 | 需要的 n |
   |---|---|
   | 0.2 σ | **196** |
   | 0.3 σ | 87 |
   | 0.5 σ | 32 |
   | 1.0 σ | 8 |

   反过来，**逐品种配对（n = 59）的最小可检出效应是 0.36 σ**（`2.80 × σ_d/√59`）。任何小于这个量级的改进，在 59 个品种的配对设计下**根本看不见** —— 看到了也是噪声。每个 n=59 的测试都要把这句话写在结论旁边。

   由于逐品种收益高度非正态（零膨胀 + 厚尾），优先用 **Wilcoxon 符号秩**而不是配对 t；上表的 n 对 Wilcoxon 近似适用（正态下 ARE = 0.955，厚尾下更优）。

# §1 日夜分开到底值不值得

## 1.1 现状

`split` 是默认时段模式（`src/data/v3_sessions.py:194-201`）：夜盘、日盘各算一个时段，各自最多一笔，**各自结束时强制平仓**（`rbreaker_backtest.py:203-206`，出场原因 `SESSION_END`）。持仓永不跨时段。

五种模式已经参数化，v3.0 也跑过 59 品种 × 5 模式 × 2 策略的对比表。

## 1.2 但那张表回答不了这个问题

**这是本节最重要的一句话。**

`split` 与 `day_night` 的差异同时包含三样东西：

| 混杂项 | 内容 |
|---|---|
| **(a) 边界跳空暴露** | 合并后持仓穿过 15:00→21:00 的停盘 —— **这才是我们要问的** |
| (b) 节流阀 | 「每时段一笔」在合并后从一天两笔变成一天一笔 |
| (c) 线下标 | `day_night` 的夜盘部分用的是**旧一天**的六条线（`时段模式方案 §1`，这是唯一无未来函数的选择，但它改变了信号） |

实测里 (b) 和 (c) 的影响远大于 (a)：合并后持有时长从 113 根涨到 166 根，跳空成交从 48 笔涨到 220 笔（4.6 倍）。**净收益中位数的差异（−1.48% vs −0.66%）无法归因给其中任何一项。**

**正确做法是把 (a) 单独隔离。** 而这不需要跑任何新的策略配置 —— 现有 `split` 模式的每一笔 `SESSION_END` 出场，都自带一个天然的反事实问题：「如果不平，下一个时段开盘会怎样？」

## 1.3 用户提的那个具体情形

> 我们在做多，采用日夜分开，导致错过了夜盘开盘的多头跳空。

这正是 TEST-1B 要测的量。注意它是**有符号**的：错过有利跳空是成本，避开不利跳空是收益。两者是同一个分布的两侧，不能只数一侧。

## 1.4 测试

```
TEST-1A   时段边界跳空的无条件分布                            [A 类]
─────────────────────────────────────────────────────────────
问题      时段边界的跳空有多大？形状是什么？是否有方向性漂移？
观测单位  一个时段边界（前一时段末根 → 后一时段首根）
总体/窗口 59 品种 × 全历史；排除 P0-2 / P0-3 / P0-5 覆盖的边界
统计量    g_norm = [(open_next − close_prev) / close_prev] / σ_d
          σ_d = 该品种当时的日 ATR 占收盘价百分比（不归一化则 AU 与 RB 不可比）
分层      ① 边界类型 {日→夜, 夜→日, 周末(55~58h), 节假日}
          ② 品种（28 有夜盘 / 31 无夜盘分开）
配对      不配对（描述性）
输出      逐层直方图 + 分位数表 + ECDF 叠加图
n 口径    n_逐品种：有夜盘约 8,000 / 无夜盘约 4,000
          n_汇总：日→夜 ~112,000 · 夜→日 ~112,000 · 周末 ~22,000
          n_有效：约 4,000（按 trading_date 的块数，不是 246,000）
判据      无，仅测量
功效      n 极大，任何有实际意义的效应都可检出；瓶颈在 n_有效 ≈ 4,000
```

```
TEST-1B   方向加权的边界跳空 —— 决定性的那一个                 [A 类]
─────────────────────────────────────────────────────────────
问题      在策略实际持有仓位的那些边界上，跳空是站在我们这边还是对面？
观测单位  一笔 SESSION_END 出场（split 模式，突破与反转分开统计）
总体/窗口 59 品种 × 全历史；过滤同 1A；剔除后面无时段的边界
统计量    g_signed = dir × g_norm      （dir = +1 多 / −1 空）
分层      ① 策略 {突破, 反转} ② 边界类型（同 1A）③ 出场时的浮盈符号
配对      不配对
输出      直方图 + 分位数表；**均值的块 bootstrap 95% CI 是关键读数**
n 口径    n_逐品种：突破约 1,300 / 反转约 950（由 5,047 与 3,697 外推）
          n_汇总：突破约 80,000 · 反转约 58,000
          n_有效：约 4,000
判据      无，仅测量（但它直接喂给 1C 的判据）
功效      n_有效 = 4,000 ⇒ 可检出 0.044 σ 的均值偏移，足够
```

**怎么读这个分布**（写给 boss 的一句话）：

- `E[g_signed] ≈ 0`，尾巴厚 → **分离在期望上不花钱，纯赚方差缩减。分开是免费的午餐，保留。**
- `E[g_signed] > 0` 且显著 → 隔夜动量真实存在，**分离是在花钱买保险**，接下来要问买得值不值（1C）。
- `E[g_signed] < 0` → 边界跳空系统性对持仓不利，**分离不仅免费还赚钱**，甚至该考虑主动在边界前平仓。

```
TEST-1C   反事实：多持有一个时段的 ΔPnL                        [B 类]
─────────────────────────────────────────────────────────────
问题      把 SESSION_END 改成「再持有恰好一个时段」，逐笔收益怎么变？
观测单位  一笔 SESSION_END 出场
总体/窗口 59 品种 × B 类训练窗（2023-01 ~ 2025-06）
统计量    ΔPnL = PnL(多持一个时段) − PnL(时段末平仓)，以 R 为单位
          反事实规则**最小化**：同一套追踪止损几何、同样的时段末强平，
          只是把强平点推后一个时段。不引入任何新参数。
分层      策略 × 边界类型
配对      **同一笔交易**（这是最强的配对：完全相同的入场，只有出场规则不同）
输出      ΔPnL 的直方图 + 分位数表 + 逐品种均值的分布（n=59）
n 口径    n_逐品种约 200 · n_汇总约 11,700 · n_有效约 600
判据      **预注册**：保留分离 ⟺
            median(ΔPnL) ≤ +0.05 R  或  p5(ΔPnL) ≤ −1.0 R
          （即：多持有的中位收益不足 0.05R，或其 5% 分位亏损超过 1R）
          两个条件任一成立即保留现状。**阈值在看到数据前写死。**
功效      n_有效 = 600 ⇒ 可检出 0.11 σ；充足
```

**为什么判据要写成「中位数 + 尾部分位」而不是均值**：这是一个典型的「小赚 vs 偶尔巨亏」权衡，均值会被少数几个巨大跳空主导，而那正是我们要防的东西。用中位数衡量常态收益、用 p5 衡量尾部代价，两者分开表述，决策才清楚。

# §2 中国商品期货涨跌停板

## 2.1 现状：零实现、零数据

grep `涨停|跌停|limit_up|limit_down|停板|settle` 覆盖全仓 —— `src/` 与 `tests/` **零命中**。

后果有三条，都是**单向乐观偏差**：

1. **板上能开仓。** 突破信号恰恰最容易在剧烈单边行情里触发，而那正是最可能封板的时刻。想追多时封涨停买不进 —— 信号有效但不可执行，且方向系统性对策略不利。
2. **止损在封板时仍按正常撮合。** 现实是价格已穿过但无对手方，仓位被锁死，敞口持续放大到次日。回测里这一笔按止损价干净出场了。
3. **反转策略在板附近逆势开仓完全无约束。** v3.0 的反转方案 §7.3 已经把这条记在案：「距板一定幅度内禁反向开仓 —— 本次不实现（仓库没有停板数据），记录在案」。

## 2.2 数据采集规格

### 2.2.1 为什么现有数据推不出停板价

停板价的基准是**昨结算价，不是昨收盘价**（`docs/04-参考资料/v3.0-RSCH-中国商品期货市场结构化参考.md:119`：「用收盘价算停板是回测中的高频错误」）。

而**结算价在现有三层数据里都不存在**：

| 层 | 列 | 有结算价吗 |
|---|---|---|
| raw txt | `CLEARINGDAY, TDATE, CONTRACTID, MARKET, [Offset], bartime, closeprice, openprice, highprice, lowprice, volume, value, vwap, OPENINTS` | **否** |
| 主力连续 pkl | 同上 + 主力判定 + 复权因子 K | **否** |
| clean_1m parquet | `open, high, low, close, volume, total_turnover, open_interest, contract, K, trading_date` | **否** |

所以停板价**既读不到也反推不出来，必须外部采集**。

### 2.2.2 要采什么

**最小字段集，逐合约逐交易日：**

| 字段 | 用途 | 口径 |
|---|---|---|
| `settlement` 结算价 | 推次日停板价的基准 | **裸价（复权前）** |
| `limit_up` / `limit_down` 涨跌停价 | 若数据源直接提供则优先取，省去自算 | **裸价（复权前）** |
| `limit_pct` 涨跌停板幅度 | 无停板价时用 `settlement × (1 ± pct)` 自算 | 逐品种逐日，交易所会动态调整 |

**「必须是裸价」这一条是本节最容易出错的地方，单独强调：**

- 策略帧永远后复权（`src/data/v3_sessions.py:101-115`，`adj = close/K*k0`，且**没有关闭开关**）。
- 停板是**绝对价格逻辑**，只在裸价空间里成立。`data/03-pkl层/v3.0-SPEC-数据质量排查判据.md:34` 写死了这条规则：「保证金、手数、跳价、**停板**等绝对价格逻辑必须用裸 `close`，只有收益率/指标用 `close/K`」—— 铁矿石复权价是真实价的 **8.63 倍**。
- **因此采集必须落在裸价上，然后用同一天的 `K` 和同一个 `k0` 做与 bar 完全相同的变换**，才能和策略帧比较：`limit_up_adj = limit_up_raw / K_that_day * k0`。
- `k0` 的取法必须与策略帧一致（`v3_sessions.py:585`，显示窗口首根的 K）。这是 v3.0 已经踩过的坑（突破方案 §10.4「复权与 k0 耦合」）。

**采集入口**：`data/03-pkl层/check_db/jydb.py` 已能连聚源 JYDB（SQL Server）查 `Fut_*` 表，目前只用于 QC、未接入 `src/`。这是现成且最短的路径。

### 2.2.3 封板判定

1 分钟 bar 看不到盘口，只能用价 + 量的联合条件。建议的判定（阈值由 TEST-2A 标定，不预设）：

```
触板  ：high >= limit_up   （或 low <= limit_down）
封板  ：bar 的 high == low == limit_up  且  volume 低于该品种该时段成交量的某分位
```

`data/03-pkl层/排查脚本/qc_final_sweep.py:171-172` 已有一个更粗的启发式代理：`locked = (整日 high == low) & (整日 volume > 0)`，全历史命中 **176 个 (品种, 交易日)**。这是我们目前唯一的量级参考，也是 TEST-2A 的对照基准。

### 2.2.4 要新增的两条撮合规则

| # | 规则 | 影响 |
|---|---|---|
| **R1** | 封板 bar **禁止同方向成交**：涨停封板时不许买入开仓 / 不许空头平仓；跌停封板时反之 | 直接堵住「板上开仓」 |
| **R2** | 止损在封板期间**无法成交**，成交推迟到开板后第一根（按该根 open） | 把「止损失效」这个真实风险搬进回测 |

这两条会**降低**历史绩效。这是回测向实盘靠拢的正确方向，不是退步。

# §3 参考价 / 波动率 / 有偏性的泛化

## 3.0 先说一件必须说清楚的事：代码和 boss 的文档不是同一个公式

`v4.0-MEMO-R-Breaker公式泛化讨论.md` 分析的是 **pivot 变体**：

```
P = (H+L+C)/3        R = H − L
Bbreak = H + 2(P−L)      Ssetup = P + R      Senter = 2P − L
Benter = 2P − H          Bsetup = P − R      Sbreak = L − 2(H−P)
```

v3.0 代码跑的是 **f1/f2/f3 变体**（`src/strategy/rbreaker.py:130-141`）：

```
Ssetup = H + f1(C−L)               Bsetup = L − f1(H−C)
Senter = ((1+f2)/2)(H+C) − f2·L    Benter = ((1+f2)/2)(L+C) − f2·H
Bbreak = Ssetup + f3(Ssetup−Bsetup)   Sbreak = Bsetup − f3(Ssetup−Bsetup)
                                       f1=0.35  f2=0.07  f3=0.25
```

**两套公式数值不等。** 同一天 H=110 / L=90 / C=100：

| | Bbreak | Ssetup | Senter | Benter | Bsetup | Sbreak |
|---|---|---|---|---|---|---|
| v3.0 (f1/f2/f3) | 120.25 | 113.5 | 106.05 | 93.95 | 86.5 | 79.75 |
| pivot 变体 | **130** | **120** | **110** | **90** | **80** | **70** |

**已决策：v4.0 切换到 pivot 变体**，与 boss 的符号体系对齐。但下一小节要说明，这不是一次符号对齐，而是换了一个策略 —— 因此它本身必须先被测量。

## 3.1 统一参数化：锚点 × 尺度 × 形状

把两个变体放进同一个框架：

$$\text{Level}_i \;=\; A \;+\; \kappa_i \cdot S$$

- **A**（锚点 / anchor）—— 位置参数
- **S**（尺度 / scale）—— 波动率参数
- **κ_i**（形状系数）—— 有偏性住在这里

令 `c = (C−L)/(H−L)`（昨收在昨日振幅中的归一化位置），则：

| | v3.0 (f1/f2/f3) | pivot 变体（v4.0 采用） |
|---|---|---|
| 锚点 A | `M = (Ssetup+Bsetup)/2 = L + R(0.325 + 0.35c)` | `P = (H+L+C)/3 = L + R(1+c)/3` |
| A 随 c 的漂移幅度 | 0.35 R | 0.333 R |
| κ_break | **±1.0125（恒定，与偏性无关）** | ±1.5 |
| κ_setup | **±0.675（恒定，与偏性无关）** | ±1.0 |
| κ_enter | ±0.3025 + 0.185(c−0.5) | ±0.5，具体为 `δ_H = ωR`，`ω = (2−c)/3` |
| Senter − Benter | **0.605 R** | **1.0 R** |
| Bbreak − Ssetup | **0.3375 R（恒定）** | **δ_L（随偏性变）** |
| 初始风险（突破多） | (0.69 − 0.185c) R ∈ [0.505R, 0.69R] | R − δ_L/3 ∈ [0.778R, 0.889R] |

*（验算：非对称用例 H=110 / L=90 / C=108，c=0.9 → v3.0 得 M=102.8、Ssetup=116.3、Senter=110.33、Benter=98.23、Bsetup=89.3，Senter−Benter=12.10=0.605×20 ✓）*

## 3.2 三个必须说出来的结论

### 结论一：v3.0 现行代码几乎没有有偏性

看上表 κ 那三行：**v3.0 的突破层和观察层是恒定的**，四条线（Bbreak / Ssetup / Bsetup / Sbreak）钉在 M 的固定倍数上，与昨收位置 c 完全无关。**只有 Senter / Benter 一对带偏性**，而它们是一把间距恒为 0.605R 的刚性尺，整体滑动范围只有 **±0.0925R（总摆幅 0.185R）**。

也就是说：boss 文档花大量篇幅分析的「恐高症模型 / 非对称惩罚 / 二阶扩张」机制，**在现行代码里基本不存在**。

### 结论二：切到 pivot 不是符号对齐，是换策略

| | v3.0 | pivot | 变化 |
|---|---|---|---|
| 观察层带宽（κ_setup） | 0.675 | 1.0 | **+48%** |
| 反转死区（Senter−Benter） | 0.605R | 1.0R | **+65%** |
| 偏性摆幅 | 0.185R | 0.333R | **1.8×** |
| 初始风险 | 0.505~0.69R | 0.778~0.889R | **约 +30%** |

带宽变宽 ⇒ **Ssetup 触碰率下降** ⇒ 而**反转策略必须先触碰 Ssetup 才能武装** ⇒ 反转成交笔数会显著下降。这会改变本文每一节的 n。

**所以 TEST-3A 是全文的前置。**

### 结论三：ω 是纯平移算子，做不了别的

在 pivot 骨架下代入 `δ_H = ωR, δ_L = (1−ω)R`：

```
Bbreak = P + (2−ω)R      Senter = P + (1−ω)R
Benter = P − ωR          Sbreak = P − (1+ω)R
```

对 ω 求导，四条线**全部等于 −R**。于是它们之间的间距是 ω 的不变量：

$$B_{break} - S_{enter} \;=\; S_{enter} - B_{enter} \;=\; B_{enter} - S_{break} \;=\; R$$

**Bbreak / Senter / Benter / Sbreak 永远是一把间距恰好为 R 的刚性四级梯子；ω 只能把这把梯子整体上下平移，而 Ssetup / Bsetup 钉死在 ±R 不动，充当固定参照框。**

```
        ω = 0.2              ω = 0.5              ω = 0.8
  +1.8 ─┬ Bbreak
  +1.0 ═╪═ Ssetup      +1.5 ─┬ Bbreak
  +0.8  ┼ Senter       +1.0 ═╪═ Ssetup      +1.2 ─┬ Bbreak
        │              +0.5  ┼ Senter       +1.0 ═╪═ Ssetup
  −0.2  ┼ Benter             │              +0.2  ┼ Senter
  −1.0 ═╪═ Bsetup      −0.5  ┼ Benter             │
  −1.2 ─┴ Sbreak       −1.0 ═╪═ Bsetup      −0.8  ┼ Benter
                       −1.5 ─┴ Sbreak       −1.0 ═╪═ Bsetup
                                            −1.8 ─┴ Sbreak
   （═ 固定框，┼ 刚性梯子，梯级间距恒为 R）
```

**推论**：无论把 ω 换成 RSI、偏度还是 HMM 状态，能做的只有「把梯子推上或推下」。想让「反转回撤距离」与「突破间隙」独立变化 —— 例如强势时突破更近**同时**反转回撤也更宽 —— 在 `δ_H + δ_L = R` 约束下**数学上不可能**，因为两者之和恒为 R。要那个自由度必须引入第二个参数（`δ_H = ωKR, δ_L = (1−ω)K'R`），而那已经超出 boss 文档提的三维泛化。

## 3.3 我的建议：优先级与 boss 文档相反

boss 文档的递进是 **R → ω → P**。**我建议 P → S → ω**，理由三条：

| 维度 | 类型 | 一单位误差的后果 | 新增自由度 |
|---|---|---|---|
| **A（锚点）** | 位置参数 | 六条线**整体平移** δ —— 最大的系统性误差 | 1（估计量选择） |
| **S（尺度）** | 尺度参数 | 第 i 条线移动 `ε·κ_i·S`（0.5~1.5 倍） | 2（N1, l） |
| **κ（偏性 ω）** | 纯平移算子 | 只滑动梯子，摆幅上界 ±R/3 | **4**（N2, mode, W_min, W_max） |

**效应最小、参数最多，投入产出比最差 —— 所以 ω 排最后。**

**第二条理由更重要：P 才是 1 分钟数据的真正优势所在。** 日线 ATR 是任何拿到日线数据的人都能算的；**昨日成交量最密集价（POC）或 VWAP 是日线版 R-Breaker 结构上无法使用的信息。** 如果 v4.0 的意义是用上那 5,900 万根 1 分钟 bar，P 是唯一的着力点。用户自己在提问里已经指向这个方向（「把 reference price 往昨日权重最密集的价格调整」），这个直觉是对的，而且它比 ATR 更有价值。

## 3.4 关于系数 `l`：应该解出来，不是拍 1.2~1.5

boss 文档建议 `R_stat = l · ATR(N)`，`l = 1.2~1.5`。**这个取值会出问题：**

pivot 骨架的 `κ_setup = 1.0`，而 v3.0 现行是 0.675。若再乘 1.5，观察层落在 `P + 1.5·ATR`，是现行 `M + 0.675·R` 的约 **2.2 倍**。Ssetup 触碰率会崩塌，反转策略的武装条件几乎无法满足。

**`l` 不是一个要调的参数，是一个要解的未知数。** 定义方式：解 `l` 使得新旧两套线的 **Ssetup 触碰频率相等**（或次一级：`median(l·ATR_N) = median(R_prev)`）。这样 A/B 比较的才是**估计量的方差**，而不是「带宽变宽」这个平凡差异。

**这是本节最重要的实验设计要点，也是 boss 文档完全没有涉及的一点。** 不做尺度中性校准，TEST-3D 测出来的东西没有意义。

# §4 突破的跳空入场

## 4.1 代码事实

三条，都在 `src/engine/rbreaker_backtest.py:240-259`：

**(1) 入场判据是「电平」不是「穿越」**（`:245`）

```python
up, dn = hi[j] > BB[D], lo[j] < SBK[D]      # j = i − 1
```

只要 bar i−1 的最高价**高于** Bbreak 即触发。价格一旦站上 Bbreak，**之后每一根都满足这个条件**。

**(2) 成交价与止损位活在两个不同的空间**（`:251-255`）

```python
entry_i, entry_px, entry_t = i, float(op[i]), ...   # 成交在 bar i 的 open
theo = BB[D] if up else SBK[D]
peak = theo                                         # peak 种在**理论线**上
trail_arr[i] = (SE[D] + (theo − SS[D]) / d) if up else ...
```

`peak` 和初始止损都由 `theo = Bbreak` 算出，与实际成交价 `op[i]` 无关。设计意图写在 `:62-68`：成交价与理论线之差「全额计入盈亏、零传导到止损位」。

**(3) 后果：实际风险随跳空幅度 1:1 膨胀，且无上限**

令 `G = op[i] − Bbreak`（越线幅度），则：

```
名义初始风险 = Bbreak − stop      （pivot 骨架下约 0.78 ~ 0.89 R）
实际初始风险 = op[i] − stop = 名义风险 + G
```

**G 没有任何上限。** 一次 2R 的跳空开盘就能把这一笔的实际风险变成名义值的三倍多。而这**不体现在成交笔数上，只体现在单笔风险分布的右尾上** —— 现有的九行统计面板完全看不到它。

**(4) 跳空开盘的实际路径**：时段首根不入场（`:242` 的 `not first_of_sess[i]`），所以高开越线时是「首根 high > Bbreak → **第二根 open 成交**」。让掉一根，但只让一根。

## 4.2 关于重入：你的猜测是对的，而且比你想的更严重

> 如果我做多，价格超过 bbreak 进场，然后被止损了，但整个过程价格都在 bbreak 之上。下一根 K 线来的时候是直接进场吗？
> （想了一下，现在有个单个时间段一笔 trade 的 lock，所以这种情况应该不会发生）

**代码确认：现状不会发生，但原因不是你以为的那个。**

- `one_trade_per_session`（`src/strategy/rbreaker.py:67`，默认 `True`）在 `rbreaker_backtest.py:241` 挡住了同时段重入。已有测试证实关掉后会重入：`tests/test_rbreaker_backtest.py:153-164`（1 笔 → 2 笔）。
- **但因为入场是电平不是穿越，关掉锁之后不是「偶尔重入」，而是「止损出场后下一根立刻重新入场」，只要价格还在 Bbreak 之上就会一直循环。**

**结论：这个锁在兼职做去抖（debounce），不是单纯的节流阀。** 拿掉它等于换了一个策略，不是「放开一个限制」。这一点必须写进任何放开该锁的方案里 —— 而 §5 的合成方案正好要放开它。

## 4.3 要建的过滤器

**真穿越（true cross）判定**：信号 bar 必须真的**跨过**该价位，而不是整根都在它之上。

```
真穿越 ⟺ low[j] ≤ Bbreak ≤ high[j]        （做多；做空对称）
跳空   ⟺ low[j] > Bbreak                  （整根在线上方，价格没在这里成交过）
```

**关键设计建议：不要把跳空二值化。**

对每一笔入场测量**连续量** `G/R`；「跳空」只是这个分布的右尾。这样 n = 全部入场笔数（约 11 万笔全历史），而不是稀疏的「跳空笔数」（一年只有几十笔）。过滤阈值 `G*` 从条件绩效曲线上解出来，而不是靠二分类拍一个。

# §5 突破与反转如何拼成一个

## 5.1 R-Breaker 的原始设计意图

用一句话概括：**把当天分成两种走势 —— 要么趋势、要么反转；判错一次还有二次机会；判对就当天 TP。**

- 开盘判成趋势（追突破），若走出反转，策略自适应切换到反转逻辑，尝试赚回一点、减少判错的损失。
- 判对了就当天了结。

## 5.2 现状与它的距离

| | 原始意图 | v3.0 现状 |
|---|---|---|
| 结构 | 一个状态机，六条线共用 | **两个完全独立的引擎**，各跑各的 |
| 二次机会 | 突破止损后反手 | 两个引擎互不知道对方存在 |
| 节流 | 一天一个剧本 | 各自「每时段一笔」，互不占用名额 |
| 当天 TP | 判对即了结 | **完全没有止盈**，只有追踪止损 + 收盘强平 |

**唯一已经成立的事实**：逐品种净收益相关系数 **+0.145**，两者近乎正交。这是合成的硬理由 —— 但正交性只保证「一起跑能摊平波动」，**不保证「按形态择一能更好」**。这两件事必须分开验证。

## 5.3 必须点破的关键问题

**形态标签是事后的。**

若测试只证明「事后知道当天是趋势日还是反转日，就能挑对策略」，那等于证明「知道未来会赚钱」—— 完全无用。所以整节的成败系于 **TEST-5C：形态在时段开盘时刻可否事前判别？**

这一点要在文档和汇报里都说清楚，否则 5B 那张漂亮的分层表会被误读成结论。

## 5.5 合成方案的两个变体（待 5C 裁决）
