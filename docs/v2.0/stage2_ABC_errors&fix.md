## A 组 — 直接扭曲结果

### A1. 触碰检测 close → high/low　【代码】★★★（主因）
- **位置**：`pullback_backtest.py:124-125`（腿 A `hit_tp`/`hit_sl`）、`:155-157`（腿 B `hit_trail`），现均比较 `price = row["close"]`（`:116`）。
- **错误（逻辑链）**：只用 5m 收盘判触碰 → bar 内 low 刺穿止损但 close 收回 = **不止损**（近端障碍被系统性豁免，删掉的几乎全是亏损）→ 胜率虚高、亏损尾部消失。close 口径下 SL 与 TP 天然互斥，掩盖了真实的「先被打到哪个」问题。
- **修复**：改挂单语义——
  - 多头：`hit_sl = row["low"] <= stop`；`hit_tp = row["high"] >= trigger`；`hit_trail = row["low"] <= trail`。
  - 空头对称（sl 用 high、tp 用 low、trail 用 high）。
- **联动·方向**：引入**同根双触**（一根 bar range 同时穿 SL 和 TP）——必须补显式优先级：**同根同时命中按 SL 处理**（保守，近端先被打概率高）。方向：胜率下移 3–7pt。**头号 Sharpe 失血点。**

### A2. 成交价跳空修正　【代码】★★★（口径已收窄）
- **位置**：`:129`（`exit_price=batch.stop_loss`）、`:162`（`exit_price=batch.trailing_stop`）；止盈 `:139`（`exit_price=trigger`）。
- **错误（修正后口径）**：连续行情下单根 5m bar 内穿越时，`stop` 是真实成交过的价，记 `stop` **公允**（占绝大多数）。被抹掉的**只剩**「触发那根 bar 的 `open` 已越过 `stop`」的情形——主渠道是**隔夜跳空**（持仓过夜，次日 09:30 直接跳穿），外加极少数盘中 news-gap。方向性结论（尾部亏损被截断 → MaxDD/方差失真）保留。
- **修复**：止损成交价取更差一侧——多头 `exit = min(stop, row["open"])`，空头 `max(stop, row["open"])`；吊灯同理取不利侧。**止盈是 limit 单**，保持 `exit = trigger`（不给跳空额外便宜），形成「止损吃亏、止盈不占便宜」的保守不对称。
- **联动·方向**：与 A1 同一段代码，一次改完。MaxDD −0.82% → 预测 −4~−8%。

### A3. 吊灯 extreme 的 intrabar 未来函数　【代码】★★
- **位置**：`:117-120` 用**当根** high/low 更新 `extreme_since_entry`，`:152-154` 立刻用它算 `trailing_stop`，`:155-157` 再判触碰——出场价 `high_i − 3ATR` 依赖本根 high。
- **错误（逻辑链）**：本根 high 在「判断本根价格是否触发吊灯」时尚未完全已知，用它抬高 trail → 出场价系统性偏乐观（多头把出场价记高）。
- **修复**：改「先判、后更新」——(1) 用**截至 i-1** 的 `extreme` 算 `trail`；(2) 用当根 high/low（A1 口径）判 `hit_trail`、按 A2 定成交价；(3) **判定之后**再用当根 high/low 更新 `extreme`，供下一根用。
- **联动·方向**：与 A1/A2 同段，腿 B 出场价归正、略降收益。

### A4. 交易成本全链路为零　【代码】★★★（新增 module）
- **位置**：`portfolio_pullback_backtest.py:163` `fee_pct` 默认 0，且只挂组合层 turnover（`:214`）；单标的引擎零成本。
- **错误（逻辑链）**：1592 批 × ~2 腿 ≈ 4000+ 次成交、R 仅 0.4–1%，零成本回测对薄 R 策略无参考价值——期望值正负本就由成本决定。
- **修复**：新增 `costs.py`，每次成交（进/出、每条腿）扣 `commission + spread/2 + slippage`。参数分两档：liquid 单边 2bp、illiquid 4–7bp；佣金按现代零佣 ≈0。在 `pullback_backtest.py` 每次 append `Trade` 时并入 `pnl_pct`；`fee_pct` 归位到组合 rebalance turnover。
- **联动·方向**：往返 4–14bp = 吃掉 1R 的 4–14%；全年组合拖累预测 3–6%。

### A5. 冷静期时间尺度 bug（5m 计数当成 2h）　【代码】★★（已确认）
- **位置**：`pullback_backtest.py:107-108` 每根 **5m** 调 `cooldown.on_bar`；`cooldown.py:94` `self._stable_count += 1` 按**调用次数**累加。
- **错误（逻辑链）**：两次 2h 收盘间 state 恒定 → arm 后 **3 根 5m = 15 分钟**即释放（而非 3 根 2h ≈ 6 小时）。触发一场景里 2h 排列通常仍干净，故几乎必然 15 分钟解封——**冷静期实质空转**。你的原意（检查最近几根**不同的** 2h bar 是否稳定）正确，代码没做到。
- **修复**（二选一，推荐 b）：(a) 主循环只在检测到**新 2h bar 收盘**（2h 时间戳前进）时才调 `on_bar`；(b) `CooldownManager` 内记住上次计数用的 2h 时间戳，只有前进才 `+= 1`（把不变量封在类内）。
- **联动·方向**：**必须同步改单测**——`test_pullback_entry.py:96-151` 按「一次调用=一根 2h」写、全绿，正是它掩盖了 bug；改成集成口径（喂真实 5m 节奏）才能防回归。批次数 −10~20%。

## B 组 — 设计与统计层

### B6. ATR 时间框架错配 + SMA/RMA　【代码/需拍板】★★★
- **位置**：`stop_loss.py:43`、`take_profit.py:32` 用 **5m ATR**；`indicators.py:38` 用 `rolling(14).mean()`（SMA）。参考值（1.5~3×ATR、吊灯 3×ATR）全是**日线**语义。
- **错误（逻辑链）**：1.5×5m-ATR ≈ 0.15–0.4%，加 0.3% 固定 offset 后 offset 常大于 ATR 项 →「波动率自适应」退化成「固定 0.3% + 噪音」，R 被压到 scalp 量级、造出假性高胜率。SMA 对单根极端 TR 反应比 Wilder RMA 更硬、与日线经验值不同源。
- **修复**：(1) 止损/吊灯 ATR 改用**与持仓周期匹配**的周期（建议 30m，持仓从日内到数日）；(2) `atr()` 增 Wilder RMA（α=1/N）并在止损链路启用；(3) offset 从固定 0.3% 改 **0.1×ATR** 比例。
- **需拍板**：30m 还是 2h ATR 作止损基准（取决于目标持仓时长）。
- **联动·方向**：R 从 ~0.5% 抬到 1–1.8%，**2R/3×ATR 必须在 A1+A2 之后重新标定**，不能孤立改。

### B7. 样本内选型、零 out-of-sample　【流程】★★
- **位置**：`ma_filter.py:60-73` docstring 自述回调结构（30m 硬性 + 5m/15m OR）按回测 Sharpe 挑；12 标的也在已知 2024–26 行情下选定。
- **错误（逻辑链）**：结构与标的均 in-sample 拟合，5.65 里无法区分多少是真 alpha、多少是 data snooping。
- **修复**：划 holdout（如后 6 个月不参与任何选型）或 walk-forward；报告用 **Deflated Sharpe**（Bailey & López de Prado, 2014）折减多重检验偏差。**改验证流程，非改代码。**

### B8. 2h 序列 25% 是 30 分钟残缺 bar　【代码/需拍板】★★
- **位置**：390/120 = 3.25 → 每日第 4 根「2h」只覆盖 15:30–16:00（`resample.py` per-session 重采样）。
- **错误（逻辑链）**：(a) 2h 的 MA5/20/50 混入残缺 bar，名义跨度失真；(b) 冷静期「实体击穿均线」对尾盘暴力行情钝化（残缺 bar 实体天然小）。
- **修复**：(a) 首选改 **1h**（390/60=6.5，仅末根 30min 残缺，影响小得多），方向 MA 相应重标；或 (b) 保留 2h 但对末根残缺 bar 打标、MA 按「3 根完整 bar/日」处理。
- **需拍板**：2h→1h 会改变方向层响应速度与信号频率，是策略性质微调。

### B9. Sharpe rf=0 + 闲置现金　【代码】★★
- **位置**：`sharpe.py:22` 默认 `risk_free_rate=0`。
- **错误（逻辑链）**：低波动组合 Sharpe 对 rf 极敏感（2024–26 现金利率 4–5%）；空仓份额不计现金收益 = 免费放弃机会成本，双向都抬高了 Sharpe。
- **修复**：传入真实日度 rf（3M T-bill）；空仓权重加一档 rf return，或明确口径为「满仓风险预算 vs 现金」。
- **联动·方向**：单这一步 Sharpe 再降 20–30%。

### B10. IEX 单一数据源可成交性　【流程】★
- **位置**：`fetch_alpaca.py:57` `feed=IEX`（≈全市场成交量 2–3%）。
- **错误（逻辑链）**：bar 的 open/close 是 IEX 撮合价而非 NBBO 可成交价，低活跃时段打印稀疏、价格陈旧，损害「next-bar-open 成交」假设可信度。
- **修复**：升级 **SIP**（付费，拿 NBBO），或在成本模型（A4）对低活跃标的加一档点差惩罚。工程/预算决策。

### B11. 分散化只解释倍数、没解释被污染的基数　【分析】★
- **错误（逻辑链）**：「12 标的低相关 → 高 Sharpe」只解释了 `√N` 倍数，没解释单票基数本身被 A1–A4 污染；且「低相关」很大程度是各票多数日空仓（`r_s=0`）稀释出来的假象。
- **修复**：(1) 单票 Sharpe 在 A1–A4 修复后重算；(2) 改算**同时在场日**的条件相关 ρ，再代入 `单票 × √(N/(1+(N−1)ρ))`。纯分析，无代码。

## C 组 — 小缺陷与边缘情况

### C12. 部分止盈复利串接的向上交叉项　【代码】☆
- **位置**：`:142` `capital *= (1+0.5a)`（腿 A）后 `:165` `*= (1+0.5b)`（腿 B）。
- **错误（逻辑链）**：两式相乘 = `1 + 0.5a + 0.5b + 0.25ab`，多出 `0.25ab`（a 恒 >0，系统性微正偏）。两条腿本是**入场时资金**的固定分数，不应互相复利。
- **修复**：记 `capital_at_entry`，两腿分别对同一基准 `+= 0.5×pnl×capital_at_entry`，批次全平后一次落账。量级 ~0.5bp/盈利批次，低优先。

### C13. `_direction_by_day` 同日双向覆盖　【代码】☆
- **位置**：`portfolio_pullback_backtest.py:104-111`，`direction_by_day[d] = legs[0].direction`，dict 后写者胜。
- **错误（逻辑链）**：同一日先后两个不同方向批次时，后者覆盖前者的方向标签，贡献度分解归错方向。
- **修复**：值改成「当日各方向的美元贡献」分别累加，不用单一 direction 标签覆盖；或按 bar 数加权拆分同日两段。仅污染 contribution 报表，低优先。

### C14. 日期窗口 UTC 午夜边界　【代码】☆
- **位置**：`run_phaseF.py:27` `df["timestamp"] <= END`（END="2026-07-17"）在 tz-aware UTC 序列上裁到 7/17 00:00 UTC → 实际最后交易日 7/16；docstring 又称「clip 到共同重叠区间」，与固定窗口不符。
- **修复**：END 用 `< "2026-07-18"` 或显式 tz-aware Timestamp；同步订正 docstring。

### C15. 数据末尾未平仓批次不进统计　【代码/需拍板】☆
- **位置**：主循环结束时仍 open 的 `batch` 只把浮盈留在 equity，不进 `trades`。
- **错误（逻辑链）**：批次统计（胜率/payoff/贡献）与净值口径不一致。
- **修复**：末 bar 强制 mark-to-market 平仓计入 trades（reason 标 `EOD`），或明确两个口径都排除并注明。**需拍板**取哪种。

### C16. benchmark 描述与实现不符　【流程】☆
- **位置**：审计报告称「等权买入持有」，代码实为**逆波动率加权**买入持有（`portfolio_pullback_backtest.py:216-219`，套的是策略同款每日权重）。
- **修复**：改文档口径为「逆波动率加权买入持有」。比较本身仍公平（隔离择时变量），纯描述订正。

### C17. MaxDD 用日频收盘净值　【代码】★
- **位置**：MaxDD 基于日频净值，日内回撤不可见，叠加 A2 跳空抹除 = 双重低估。
- **修复**：改用 **5m 频**净值算 MaxDD，或标注「日频 MaxDD 为下界」。与 A1/A2 修完一起重算才有意义。

### C18. bias 翻转/转 neutral 不平已有仓　【需拍板】★
- **位置**：`pullback_entry.py:47-51` 只清回调状态，持仓靠止损体系离场。
- **错误（逻辑链）**：「2h 定方向」依据消失后仓位照旧，持仓期方向暴露与信号框架脱钩。
- **修复**：(a) 保留现设计但**单独统计**这类「方向已反但仍持有」批次的 PnL；(b) 改成 bias 反转即平仓。策略性质分叉，**需拍板**；至少先做 (a) 看影响。

### C19. 入场触发不要求 30m 回同向　【代码/需拍板】☆
- **位置**：`ma_filter.py:86-88` `get_entry_trigger` 只查 5m+15m（AND），回调却要求 30m 反向。
- **错误（逻辑链）**：存在「30m 仍反向时入场」窗口，与「多周期共振」叙事不完全一致。
- **修复**：可选在 `get_entry_trigger` 加「30m 不再反向（neutral 或同向）」。会降信号频率，**需拍板**权衡样本量。

### C20. 跨夜信号无时效折扣　【需拍板】★
- **位置**：15:55 触发的信号按次日 09:30 开盘成交，止损/触发价全基于昨日 ATR 与 30m 结构。
- **错误（逻辑链）**：隔夜信息（跳空、隔夜新闻）未被处理，信号已陈旧仍照单成交。
- **修复**：(a) 丢弃当日末 N 根 bar 生成的信号；或 (b) 次日开盘用最新数据重新校验触发。策略取舍，**需拍板**。

### C21. 空头分红成本被复权抹掉　【流程】☆
- **位置**：`fetch_alpaca.py:58` `Adjustment.ALL` 抹平除息跳空。
- **错误（逻辑链）**：做空跨除息日实际要付股息，回测未扣。
- **修复**：对空头持仓跨除息日补扣股息成本（需除息日历数据）。量级小，可先在成本模型（A4）留接口、暂标 TODO。

### C22. `MarketSnapshot.atr` 死参数　【代码】☆
- **位置**：`pullback_entry.py:26` 传入 `atr`，但 `on_bar` 从不使用。
- **修复**：删字段；或若 B6 要在入场层用 ATR 做「平台位过近保护」，则接上它。纯卫生。

|---|---|---|
| **第一刀** | A1 + A2 + A3 | 同一段主循环：挂单语义 + 跳空 + 吊灯顺序一次改完，重跑即可定性 edge 真伪 |
| 第二刀 | A5 + U1 | 冷静期真正生效 + 决策前移，信号频率归正（连带改单测） |
| 第三刀 | A4 + C21接口 | 成本模型，吃掉薄利 |
| 第四刀 | B6 + B8 | ATR 周期/RMA + 1h 改造，**必须在前三刀之后重标定** 2R/3×ATR |
| 收尾 | B9, C12–C17, C22 | 报表/口径/边缘，逐条清 |
| 流程 | B7, B10, B11 | 非代码：holdout、SIP、条件相关 |
| 需拍板 | B6, B8, C15, C18, C19, C20 | 六个设计分叉，动手前需 manager 定 |

**纪律**：每改一刀单独重跑，留 `Sharpe / 胜率 / MaxDD / 批次数`，做成「每修一个 bug，Sharpe 掉多少」的瀑布表——这是给 manager 最有说服力的一页。
